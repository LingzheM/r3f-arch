01这一步解决什么问题

不是「加两种节点」。是「一个节点可以住在另一个节点身上」

M6 加了三种类型，证明了注册表通用。但那三种全是平级的 —— slab、ceiling、column 各自独立，删掉任何一个，其它两个毫发无损。 门窗是第一个不能独立存在的东西：

  • 门的位置只在某堵墙上才有意义。墙没了，门的坐标是一串没有参照物的数字。
  • 门会改写宿主的几何。这是第一次「A 节点的存在改变 B 节点的形状」。
  • 墙动，门必须跟着动。这是第一次非对称的联动 （M4 的墙↔墙联动是对称的：谁动都一样）。

所以 M7 真正要建的东西只有一个：宿主关系。 门窗是它的第一个用户，M8 的 Site → Building → Level 是第二个， M10 的屋顶面宿主是第三个。M7 定错了，M8 和 M10 就是在歪地基上砌墙。

五个判断。A 是地基，其余四个都长在 A 上面

A · 门窗的 position 到底在谁的坐标系里

先把事实摆清楚，再选路。

事实 1 —— 对照仓库的答案是「墙的局部坐标系」，而且不止说说。 door.ts:155 写着 position: center of the door in wall-local coordinate system； door-math.ts:22 的 wallLocalToWorld(wall, localX, localY) 做的正是 start + localX·(cos a, sin a)； wall/renderer.tsx:121 把 node.children 递归渲染在墙 mesh 内部； wall-system.tsx:794 给那个 mesh 设了 position = start / rotation.y = −angle。 四处互相印证，是一套完整的机制，不是一句注释。

事实 2 —— 我们这边这条路一行都没铺，而且比 handoff 说的更远。 handoff-m7.md ④ 写「ParametricNodeRenderer 的 position 绑定（第一条路已通）」。 实际读代码：

两条路

路 1 · 真父子

门的 group 挂进墙的 group，transform 由 three 复合。

door.parentId = wall.id；NodeRenderer 递归渲染 node.children；门的 position 就是 <group position>， 不做任何换算。

前提：墙的位姿必须搬到注册的那个 group 上。 即 buildWallGeometry 不再返回带世界 transform 的信封， 改成「纯局部几何」＋ 渲染器绑位姿。

路 2 · 信封

门平挂在场景根下，builder 自己把墙的 transform 复合进几何。

door.wallId 只是一个引用；buildDoorGeometry 里 ctx.resolve(node.wallId) 拿到墙，算出世界位姿， 烤进返回的 Object3D —— 和今天 buildWallGeometry 干的事一模一样。

前提：无。今天就能写。

// parametric-node-renderer.tsx:12-17 —— 判据是【结构性】的，不是声明性的
function positionOf(source) {
  return 'position' in source ? source.position : undefined
}                // ^^^^^^^^^^^^^^^^^ 谁有这个字段名，谁就被绑

门恰好有一个叫 position 的字段，而它是墙局部坐标。 走路 2 的话，这个字段会被渲染器当成世界坐标绑到 <group> 上， 同时 builder 又把墙的 transform 烤进几何 —— 正好平移两次， M6 预言的那个 bug 一字不差地发生。

「第三种模式」不是第三条路，是让路 1 成立的那把锁

handoff-m7.md 说的第三条路是给渲染器加 space: 'world' | 'local' | 'host'。 建议不要做成枚举，做成一个函数。枚举回答「在哪个空间」， 但真正缺的信息是「那个空间的位姿是多少」—— 墙的位姿不在 node 里， 是从 start/end 算出来的： 

// core/registry/node-definition.ts —— 新增一个可选字段
export type NodeFrame = {
  position: [number, number, number]
  rotationY: number
}

export type NodeDefinition<N, L> = {
  kind: N['type']
  frame?: (node: N, ctx: GeometryContext<L>) => NodeFrame
  geometry?: ...
  computeLevelData?: ...
  renderer?: ...
  system?: ...
}

于是三种类型的答案变成一张表，而且是声明的，不是结构猜的：

kinddef.frame结果
wall从 start/end 算group 站在 start，朝墙的方向
columnnode.position，rotationY: 0和今天完全一样
door / windownode.position，rotationY: 0因为它挂在墙下，这就是墙局部坐标
slab / ceiling不声明单位矩阵。builder 继续烤世界坐标（信封）

锁在哪：渲染器不再按名字找 position。 没声明 frame 的类型，就算加一百个叫 position 的字段， 渲染器看都不看。M6 那条「加错字段会静默平移两次」的债 从此在类型层面不可能发生 —— 这才叫还清， 而不是「写进文档提醒下一个人」。

B · 墙的坐标原点：中点 → start

选了路 1 之后有一个连带决定：墙局部坐标的原点放哪。 今天 wallTransform 用的是中点（wall/geometry.ts:31）， 对照仓库用的是 start（wall-system.tsx:794）。

建议改成 start。不是为了和对照仓库一致（那不是理由）， 是因为门的 position[0] 要存「离墙起点多远」（见 E）。 原点在中点的话，存的数和挂的数差一个 L/2， 于是 def.frame 必须知道墙长 —— 多一次 ctx.resolve， 而且墙一变长，所有门的挂载位置全变，尽管它们的 position 一个字没改。 那正是「同一个量有两个表示」的经典形态。

改动范围实测是封闭的：wallTransform 和 worldToLocalXZ 在整个 src/ 里只有 wall/geometry.ts 自己用（grep 结果 4 处，全在同一文件）。 move-tool.tsx:141 那个 midpoint 是拖拽锚点，另一回事，不受影响。

C · 开洞：D6 的 Shape+holes 在这个轴上不成立

handoff-m7.md ③ 第 3 条要求 §02「写清 Shape+holes 的天花板在哪」。 答案比「天花板」更硬：在 M7 这个场景里它压根到不了地板。

墙是这样造出来的（wall/geometry.ts:55-64）：

Shape( 平面轮廓 )  →  ExtrudeGeometry({ depth: 墙高 })  →  rotateX(−π/2)
        (u, −perp)                      沿 shape 的 z 挤出                 z → y

挤出方向是「高度」。所以往这个 Shape 里加一个 hole， 挖掉的是「平面上的一块」沿高度贯通 —— 一根从地板通到天花板的竖井， 像烟囱，不像门。

实测（three r185，你项目里那一份）：直墙 4×0.1×2.5， 在平面 Shape 上开一个 u ∈ [−0.45, 0.45] 的洞， 洞壁顶点的 y 值集合是 {0, 2.5} —— 洞从墙底一路通到墙顶。 包围盒不变，顶点数 36 → 72。这不是门，是竖井。

「门想沿厚度切，斜接想沿高度挤 —— 一个 ExtrudeGeometry 只给你一个轴。」 这句话就是 Shape+holes 的天花板，也是对照仓库 wall-system.tsx 那 1281 行和一个 three-bvh-csg 依赖存在的理由 （:1144-1157，逐个洞做 SUBTRACTION）。

为什么段切是精确的，不是近似（两条都实测过）：

  • 体积对得上。4 m 墙、0.1 厚、2.5 高、门 0.9×2.1： 三段体积和 = 0.811，墙体积 − 洞体积 = 0.811。 把轮廓换成一个带接头顶点的 5 点斜接轮廓，两边仍然都是 0.811， 裁出来的段是 5/4/4 个顶点。斜接没丢。
  • 门框内壁是真面。左段在 u = u₀ 处那个端面有 6 个顶点 （2 个三角形），法线全部 +X —— 朝着洞口。 它是一个封闭棱柱的普通外表面，不是 ExtrudeGeometry 的洞壁。

① 「洞的内壁是单面的，从洞里看会看穿」在我们这条管线上不成立。 实测：走 buildPolygonPrism 那条 (x, −y) → extrude → rotateX(−π/2) 管线， 墙 +Z 外表面法线 6/6 朝外（那个 −y 取反正是为了保住手性）， 洞壁法线 24/24 朝向洞内 —— 站在洞里看得见。 对照仓库 slab-system.tsx:85 那段注释确实存在、说的也是真事， 但那是他们自己那条管线的问题，照搬到我们这里是错的。 走段切之后这个问题连提都不用提。

② 「挖洞时洞必须和外轮廓反向 ⟹ signedArea 终于有消费者」不成立。 ExtrudeGeometry 自己就归一化绕向：外轮廓不是 CW 就 reverse()， 每个洞是 CW 就 reverse()（three.core.js:36317 / :36327，r185）。 实测：洞与外轮廓同向 / 反向两种输入， 产出的洞壁法线分布完全一样（24 朝内 / 0 朝外）。
所以 signedArea 在 M7 依然是零消费者。 段切也不需要它 —— 半平面裁剪保持绕向。这条债应该从 STATE.md 里 撤销，不是关闭。

D · 拾取墙面：不用新造射线

handoff-m7.md ② 说 eventToGround 只和 y=0 求交，门窗要落在墙面上 「这套彻底不够用了」—— 前半句对，后半句的结论走偏了。 不需要自建射线，因为 R3F 的指针事件已经带着命中结果了。

对照仓库的做法就一行（use-node-events.ts:21）：

实测：按我们的场景图搭一遍（注册 group → body group 带位姿 → mesh 无位姿）， 斜墙 (1,1)→(4,5)，取墙面上「离起点 1.5 m、高 1.2 m、左面」的世界点， mesh.worldToLocal() 得到 [−1, 1.2, 0.05]， 和 [u − L/2, 高度, +t/2] 的预期逐位相等。 （改成路 1 之后原点搬到 start，这里就直接是 [1.5, 1.2, 0.05]。）

再加一个字段就齐了：e.face.normal。

three 的 face.normal 是对象局部空间的 （three.core.js:23776，由 Triangle.getNormal 从局部顶点算出， 之后不乘 matrixWorld）。 墙 mesh 相对 body 没有自己的 transform， 所以 face.normal.z > 0 ⟺ 命中左面（D3 的 leftNormal 侧）。 一个点积都不用算就知道门朝哪边。

写成 e.eventObject.worldToLocal(...) 会得到世界坐标 —— 在原点附近的墙上看起来「差不多对」，把墙拖到 (20, 0, 30) 之后门就飞了。 又一个 verify 全绿的静默 bug。

代价 / 副作用：sceneRegistry.byType （M1 就写入、至今零读者）在 M7 仍然没有读者。 handoff-m7.md ④ 预期它会在 M7 迎来第一个消费者 —— 不会。 这不是遗憾：为了给一个没人用的索引找用户而自己造一套射线，是本末倒置。 它真正的用户是空间查询（M8+ 的空间网格）。

四个当场会咬人的地方

① frame 吃 effective，不是 node。 拖墙时 useLiveOverrides 里是新的 start / end， 读文档节点的话墙的几何跟着拖、位姿停在原地 —— 墙看起来在原地伸缩。 useEffectiveNode（viewer/hooks/use-effective-node.ts）已经存在， 内部就是同一个 useLiveOverrides 订阅，换过去不改变订阅行为； 无 override 时它返回 node 本身（引用不变）， 所以依赖数组能直接写成 [effective, isSelected]。

② useNodeEvents 继续传文档 node。 批 I 的判据是「屏幕上一模一样」，这里不要顺手改成 effective。 行为上等价（pointerdown 只在 idle 触发，idle 时没有 override）， 但改了就不是纯重构了 —— 纯重构里混一个语义改动，出问题时你分不清是哪个。

③ rotation-y={...}，不是 rotation={[0, y, 0]}。 后者每次渲染造一个新数组。用 R3F 的属性路径写法。

④ 循环 import 是安全的，但要知道为什么。 node-renderer.tsx ↔ parametric-node-renderer.tsx 互相 import。 安全的唯一理由是两边都只在渲染时调用对方，模块求值期不读。 NodeRenderer 是 export const（有 TDZ）， 所以哪天有人在模块顶层写 const X = NodeRenderer 就会炸。

polygon 里的 y 不是高度

Point2D 是 { x, y }，但在这里 x 是沿墙的 u，y 是离墙中面的横向偏移 （buildWallGeometry 里的 local 就是这个约定）。 高度住在 bottomY / topY，不在 polygon 里。 这两个 y 撞名会让人把「墙厚方向」当成「高度」写进去， 而结果是一个看起来能跑的退化几何。

splitWallByOpenings 的做法（形状，不是实现）

  1. 洞按 left 排序；重叠的洞合并成一个包围区间 （放置期已经挡了重叠，这里是兜底，防止段被重复计算）。
  2. 沿 u 走一遍，产出交替的区间：实墙段 和 洞段。
  3. 实墙段 → 1 个 band，[0, wallHeight]。
  4. 洞段 → 最多 2 个 band：[0, bottom]（窗台）和 [top, wallHeight]（过梁）。 高度 ≤ 0 的直接不发 —— 门的窗台段就是这样消失的。
  5. 每个 band 的 polygon = clipPolygonByU(footprint, uMin, uMax)。
三个数值陷阱

① 洞正好贴着墙端点（left = 0）。 第一段实墙的 u 区间是 [0, 0]，裁出来是空多边形或一条退化的线。 判据写成「区间长度 < EPSILON 就跳过」， 不是 uMin === uMax —— 浮点不会正好相等。

② 斜接把轮廓推到 u < 0 或 u > L。 getWallPlanFootprint 在接头处产出的点可能超出 [0, L] —— 斜接就是往外顶。所以第一段的 uMin 不能写 0， 要写 −Infinity（或一个足够负的常数）；最后一段同理。 写成 0 的话墙角会被削平，而且只在有接头的墙上出现 —— 你会以为是斜接坏了，其实是裁剪把它切掉了。

③ 绕向不用管。Sutherland–Hodgman 保持输入绕向， 而 ExtrudeGeometry 自己会把外轮廓强制成 CW（D20 / §02 C 有实测）。 这一步不需要 signedArea。

    rotationY: number,

    const sin = Math.sin(rotationY)
    const dx = p.x - position[0]
    const dz = p.y - position[2]
    return { x: dx * cos - dz * sin, y: dx * sin + dz * cos }

/**
 * 从 rootId 起收集整棵子树（含自己），深度优先。
 *
 * seen 不是为了性能，是为了让脏数据（children 成环）不把删除变成死循环。
 */
export function collectSubtree(
    nodes: Record<AnyNodeId, AnyNode>,
    rootId: AnyNodeId,
): AnyNodeId[] {
    const out: AnyNodeId[] = []
    const seen = new Set<AnyNodeId>()
    const stack: AnyNodeId[] = [rootId]

    while (stack.length > 0) {
        const id = stack.pop()!
        if (seen.has(id)) continue

        const node = nodes[id]
        if (!node) continue

        seen.add(id)
        out.push(id)
        for (const child of node.children) stack.push(asNodeId(child))
    }

    return out
}

export const useScene = create<SceneState>()(
    temporal(
        (set, get) => ({
            nodes: {},
            rootNodeIds: [],
            dirtyNodes: new Set<AnyNodeId>(),

            addNode: (input) => {
                // parse 一次同时完成三件事：填 id，填默认值，挡住非法数据。
                const node = AnyNode.parse(input)
                const parentId = node.parentId === null ? null : asNodeId(node.parentId)

                // 先校验再 set —— 在 set 里抛会让 zustand 停在半更新状态。
                if (parentId !== null && !get().nodes[parentId]) {
                    throw new Error(`[scene] addNode: 宿主 "${parentId}" 不存在`)
                }

                set((s) => {
                    const nodes: Record<AnyNodeId, AnyNode> = { ...s.nodes, [node.id]: node }

                    if (parentId === null) {
                        return { nodes, rootNodeIds: [...s.rootNodeIds, node.id] }
                    }

                    // 有父的节点【不】进 rootNodeIds —— 它由宿主的渲染器递归渲染。
                    // 进了的话会被渲染两遍：一次在世界坐标，一次在宿主坐标。
                    const parent = s.nodes[parentId]!
                    nodes[parentId] = { ...parent, children: [...parent.children, node.id] }
                    return { nodes, rootNodeIds: s.rootNodeIds }
                })

                get().makeDirty(node.id)
                if (parentId !== null) get().makeDirty(parentId)
                return node.id
            },

            updateNode: (id, patch) => {
                // 重挂宿主要同时改两边的 children，M7 不支持（排 M13）。
                // 类型上挡不住：Omit 作用在联合上会塌成公共键，
                // Partial<AnyNode> 能用是因为 Partial 是同态映射类型、会分发。
                if ('parentId' in patch || 'children' in patch) {
                    throw new Error('[scene] updateNode: parentId / children 不可 patch')
                }

                set((s) => {
                    const prev = s.nodes[id]
                    if (!prev) return s
                    return { nodes: { ...s.nodes, [id]: { ...prev, ...patch } as AnyNode } }
                })

                const next = get().nodes[id]
                if (!next) return

                get().makeDirty(id)

                // 洞挪了，宿主墙要重切。M8 的层同理。
                const parentId = next.parentId === null ? null : asNodeId(next.parentId)
                if (parentId !== null && get().nodes[parentId]) get().makeDirty(parentId)
            },

            removeNode: (id) => {
                const target = get().nodes[id]
                if (!target) return

                const doomed = collectSubtree(get().nodes, id)
                const removed = new Set<AnyNodeId>(doomed)
                const parentId = target.parentId === null ? null : asNodeId(target.parentId)

                // 整棵子树在【一次 set】里删完，撤销才是一步。
                set((s) => {
                    const nodes = { ...s.nodes }
                    for (const doomedId of doomed) delete nodes[doomedId]

                    if (parentId !== null) {
                        const parent = nodes[parentId]
                        if (parent) {
                            nodes[parentId] = {
                                ...parent,
                                children: parent.children.filter((c) => c !== id),
                            }
                        }
                    }

                    return { nodes, rootNodeIds: s.rootNodeIds.filter((n) => !removed.has(n)) }
                })

                for (const doomedId of doomed) get().clearDirty(doomedId)
                if (parentId !== null && get().nodes[parentId]) get().makeDirty(parentId)
            },

            getNode: (id) => get().nodes[id],

            makeDirty: (id) => { get().dirtyNodes.add(id) },
            clearDirty: (id) => { get().dirtyNodes.delete(id) },

            markAllDirty: () => {
                const dirty = get().dirtyNodes
                for (const id of Object.keys(get().nodes) as AnyNodeId[]) dirty.add(id)
            },
        }),
        {
            partialize: (s): SceneSnapshot => ({ nodes: s.nodes, rootNodeIds: s.rootNodeIds }),
            equality: (past, current) => areSceneSnapshotsEqual(past, current),
            limit: 50
        },
    )

import type { Point2D } from '../../lib/geometry-2d'
import { polygonArea } from '../../lib/polygon-2d'
import type { OpeningSpan } from '../../schema/opening'

/** 段的长度/高度低于这个值就不发。浮点不会正好相等，所以判区间长度，不判端点相等。 */
export const BAND_EPSILON = 1e-6

/**
 * 面积下限。点数 >= 3 不足以说明多边形非退化：
 * 裁到边界上会得到一串共线的点（见 clipHalfPlane 的去重注释）。
 * 最窄的合法段是 BAND_EPSILON x 墙厚 ~ 1e-7，所以这个阈值要远小于它。
 */
export const BAND_AREA_EPSILON = 1e-12

/**
 * 一段实心墙。
 *
 * ⚠ polygon 是墙【局部平面】轮廓：x 是沿墙的 u，y 是离墙中面的横向偏移。
 *   高度住 bottomY / topY，不在 polygon 里。两个 y 撞名，别写混。
 */
export type WallBand = {
  polygon: Point2D[]
  bottomY: number
  topY: number
}

/**
 * 用两条垂直于墙轴的半平面裁剪多边形（Sutherland–Hodgman）。
 * 绕向保持不变；结果少于 3 点时返回 []。
 *
 * uMin / uMax 接受 ±Infinity —— 首末两段必须这么传：
 * getWallPlanFootprint 在接头处产出的点会超出 [0, L]（斜接就是往外顶），
 * 写成 0 / L 会把墙角削平，而且只在有接头的墙上出现。
 */
export function clipPolygonByU(
  polygon: readonly Point2D[],
  uMin: number,
  uMax: number,
): Point2D[] {
  const lower = clipHalfPlane(polygon, uMin, true)
  const clipped = clipHalfPlane(lower, uMax, false)
  return clipped.length < 3 ? [] : clipped
}

function clipHalfPlane(
  polygon: readonly Point2D[],
  cutX: number,
  keepGreater: boolean,
): Point2D[] {
  if (polygon.length === 0) return []

  const inside = (p: Point2D) => (keepGreater ? p.x >= cutX : p.x <= cutX)
  const out: Point2D[] = []

  // 顶点正好落在切线上时，Sutherland-Hodgman 会把它输出两次
  // （一次作为“在内侧的原顶点”，一次作为“交点”）。重复顶点会让
  // ExtrudeGeometry 产出零面积三角形，而且不报错，所以在这里就去掉。
  const push = (p: Point2D) => {
    const last = out[out.length - 1]
    if (last && samePoint(last, p)) return
    out.push(p)
  }

  for (let i = 0; i < polygon.length; i += 1) {
    const current = polygon[i]!
    const next = polygon[(i + 1) % polygon.length]!
    const currentInside = inside(current)

    if (currentInside) push(current)
    if (currentInside === inside(next)) continue

    const dx = next.x - current.x
    // 一条竖直边跨不过一条竖直切线；走到这里只可能是浮点噪声，不插点。
    if (Math.abs(dx) < Number.EPSILON) continue

    const t = (cutX - current.x) / dx
    push({ x: cutX, y: current.y + (next.y - current.y) * t })
  }

  // 首尾也可能重合。
  while (out.length > 1 && samePoint(out[0]!, out[out.length - 1]!)) out.pop()

  return out
}

function samePoint(a: Point2D, b: Point2D): boolean {
  return Math.abs(a.x - b.x) < BAND_AREA_EPSILON && Math.abs(a.y - b.y) < BAND_AREA_EPSILON
}

/**
 * 墙局部轮廓 + 洞口列表 → 段列表。这就是「段切」。
 *
 * 不挖洞：把墙切成若干实心棱柱——洞左边一段（满高）、洞右边一段（满高）、
 * 洞上方过梁、洞下方窗台。门的 sill = 0 时下方那段长度为 0，直接不发。
 */
export function splitWallByOpenings(
  footprint: readonly Point2D[],
  wallHeight: number,
  openings: readonly OpeningSpan[],
): WallBand[] {
  if (footprint.length < 3 || wallHeight <= BAND_EPSILON) return []

  const spans = mergeOpeningSpans(openings)
  const bands: WallBand[] = []

  let cursor = Number.NEGATIVE_INFINITY
  for (const span of spans) {
    pushBand(bands, footprint, cursor, span.left, 0, wallHeight)
    pushBand(bands, footprint, span.left, span.right, 0, span.bottom)
    pushBand(bands, footprint, span.left, span.right, span.top, wallHeight)
    cursor = span.right
  }
  pushBand(bands, footprint, cursor, Number.POSITIVE_INFINITY, 0, wallHeight)

  return bands
}

function pushBand(
  bands: WallBand[],
  footprint: readonly Point2D[],
  uMin: number,
  uMax: number,
  bottomY: number,
  topY: number,
): void {
  if (topY - bottomY <= BAND_EPSILON) return
  if (uMax - uMin <= BAND_EPSILON) return

  const polygon = clipPolygonByU(footprint, uMin, uMax)
  // 点数不够用：裁在边界上会得到 >= 3 个共线点，面积为 0。
  if (polygon.length < 3 || polygonArea(polygon) <= BAND_AREA_EPSILON) return

  bands.push({ polygon, bottomY, topY })
}

/**
 * 排序 + 合并重叠的洞。
 *
 * 放置期已经挡了重叠（overlapsExistingOpening），这里是兜底：
 * 不合并的话同一段墙会被切两次，产出重叠的段。
 * 合并取包围盒——宁可多挖，也不要留一块悬空的墙。
 */
function mergeOpeningSpans(openings: readonly OpeningSpan[]): OpeningSpan[] {
  const sorted = openings
    .filter((o) => o.right - o.left > BAND_EPSILON && o.top - o.bottom > BAND_EPSILON)
    .slice()
    .sort((a, b) => a.left - b.left)

  const merged: OpeningSpan[] = []

  for (const span of sorted) {
    const last = merged[merged.length - 1]
    if (last && span.left <= last.right + BAND_EPSILON) {
      merged[merged.length - 1] = {
        left: last.left,
        right: Math.max(last.right, span.right),
        bottom: Math.min(last.bottom, span.bottom),
        top: Math.max(last.top, span.top),
      }
      continue
    }
    merged.push({ ...span })
  }

  return merged
}

import * as THREE from 'three'
import type { Point2D } from '../../../core/lib/geometry-2d'

/**
 * 平面多边形 → 一段 y 区间上的实心棱柱几何。不造材质、不造 mesh，
 * 所以调用方可以让 N 段共用一个材质（墙的段切就靠这个）。
 *
 * 退化输入（点数不足 / 高度非正）返回 null，而不是一个空 BufferGeometry ——
 * 空几何进了场景不报错也不显示，查起来很费劲。
 */
export function buildPrismGeometry(
  polygon: readonly Point2D[],
  bottomY: number,
  topY: number,
): THREE.BufferGeometry | null {
  const height = topY - bottomY
  if (polygon.length < 3 || height <= 0) return null

  // shape 的 y 取负：rotateX(-π/2) 会翻转手性，取负正好抵消。
  // 动了这个负号，法线全部朝内，从外面看整个体会消失。
  const shape = new THREE.Shape()
  shape.moveTo(polygon[0]!.x, -polygon[0]!.y)
  for (let i = 1; i < polygon.length; i += 1) {
    shape.lineTo(polygon[i]!.x, -polygon[i]!.y)
  }
  shape.closePath()

  const geometry = new THREE.ExtrudeGeometry(shape, { depth: height, bevelEnabled: false })
  geometry.rotateX(-Math.PI / 2)
  geometry.translate(0, bottomY, 0)

  return geometry
}

export function buildPolygonPrism({
  polygon,
  bottomY,
  topY,
  color,
  name,
}: {
  polygon: readonly (readonly [number, number])[]
  bottomY: number
  topY: number
  color: string
  name: string
}): THREE.Object3D {
  const root = new THREE.Group()

  const geometry = buildPrismGeometry(
    polygon.map((p) => ({ x: p[0], y: p[1] })),
    bottomY,
    topY,
  )
  if (!geometry) return root

  const material = new THREE.MeshStandardMaterial({ color, roughness: 0.9, metalness: 0 })

  const mesh = new THREE.Mesh(geometry, material)
  mesh.name = name
  mesh.castShadow = true
  mesh.receiveShadow = true

  root.add(mesh)
  return root
}

        const local = e.object.worldToLocal(localScratch.copy(e.point))

            node,
            point: [e.point.x, e.point.y, e.point.z],
            localPoint: [local.x, local.y, local.z],

            object: e.object,

            nativeEvent: e.nativeEvent,

        onPointerDown: (e: ThreeEvent<PointerEvent>) => {
            if (e.button !== 0) return
            emit('pointerdown', e)
        },
        onPointerUp: (e: ThreeEvent<PointerEvent>) => {
            if (e.button !== 0) return
            emit('pointerup', e)

        },

/** 沿墙轴的重叠判定。对照仓库叫 hasWallChildOverlap。 */
export function overlapsExistingOpening(
    span: OpeningSpan,
    siblings: readonly AnyNode[],
    selfId?: AnyNodeId,
): boolean {
    for (const sibling of siblings) {
        if (sibling.id === selfId) continue
        if (sibling.type !== 'door' && sibling.type !== 'window') continue

        const other = openingSpan(sibling)
        // 边对边刚好贴住不算重叠 —— 两扇门并排是合法的。
        if (span.right > other.left && other.right > span.left) return true
    }
    return false
}

/**
 * 落点 → 可提交的 position。
 *
 * 返回 { position, valid } 而不是 position | null：
 * 幽灵在「放不下」的时候【也得画出来】，画在夹紧后的位置、涂成红的。
 * 返回 null 的话幽灵会闪没。
 */
export function resolveOpeningPlacement(args: {
    hit: WallHit
    wall: WallNode
    size: { width: number; height: number }
    sill: number
    siblings: readonly AnyNode[]
    selfId?: AnyNodeId
}): OpeningPlacementResult {
    const { hit, wall, size, sill, siblings, selfId } = args

    // 先量化再夹紧。反了会得到一个没量化的边界值。
    const snappedU = snapToGrid({ x: hit.u, y: 0 }).x
    const centerV = sill + size.height / 2

    const clamped = clampOpeningToWall([snappedU, centerV, 0], size, {
        length: wallLength(wall),
        height: getWallHeight(wall),
    })

    if (!clamped) {
        // 洞比墙还大：夹不进去。给一个居中的位置让幽灵有地方画。
        return { position: [wallLength(wall) / 2, centerV, 0], valid: false }
    }

    const span = openingSpan({ position: clamped, width: size.width, height: size.height })
    const valid = !overlapsExistingOpening(span, siblings, selfId)

    return { position: clamped, valid }
}

/** 沿墙滑动：只动 position[0]，高度和进深原样保留。 */
export function slideOpeningAlongWall(args: {
    u: number
    wall: WallNode
    opening: { position: readonly [number, number, number]; width: number; height: number }
    siblings: readonly AnyNode[]
    selfId: AnyNodeId
}): OpeningPlacementResult {
    const { u, wall, opening, siblings, selfId } = args

    const snappedU = snapToGrid({ x: u, y: 0 }).x
    const clamped = clampOpeningToWall(
        [snappedU, opening.position[1], opening.position[2]],
        opening,
        { length: wallLength(wall), height: getWallHeight(wall) },
    )

    if (!clamped) return { position: [...opening.position] as [number, number, number], valid: false }

    const span = openingSpan({ position: clamped, width: opening.width, height: opening.height })
    return { position: clamped, valid: !overlapsExistingOpening(span, siblings, selfId) }
}
