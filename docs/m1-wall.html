M1 能画一堵墙

在 3D 视口里点两下地面，一堵 2.5 米高、0.1 米厚的墙立起来。按 Tab 切正交顶视， 它变成一个矩形。点击它，控制台打出它的 node id。

这就是全部。看起来一天能写完——你会用两到三周，因为这堵墙要同时把三层边界、 schema 真相源、场景注册表和坐标系约定一次性钉死。后面五个里程碑全部长在它上面。

01这一步在解决什么

四个决定，钉死之后不许再改

M1 的产出物看起来是一堵墙，实际产出物是四条此后不再讨论的约定。 每一条在原项目里都能找到对应，而每一条如果 M1 没定死，你会在 M2 到 M4 之间的某个下午 推翻重写。

① 三层边界与单向依赖

core 不许 import three。一行都不许。这不是洁癖——它是你 M2 那批几何测试能在 Node 里裸跑、不用 headless WebGL 的唯一原因，也是决策 10 （纯函数写测试）的兑现条件。viewer 不许知道"工具""选中""模式"这些词。 app 可以 import 前两者，反向永远不行。

M1 就三个目录、十几个文件，边界看起来是形式主义。原项目 390k 行时它是全部意义所在—— packages/viewer 能单独发 npm 包，正是因为这条线三年没破。

② schema 是唯一真相源

墙的一切状态只存在于一个 Zod 对象里：两个二维端点、可选厚度、可选高度。 不存长度（可算），不存角度（可算），不存 Three 对象的引用（那是 registry 的事）， 不存"是否选中"（那是 app 层的事）。每当你想往 WallNode 上加字段时， 先问一遍：这个值能不能从已有字段算出来？

③ 中心线 + 平面点约定

墙由中心线定义——原项目的 WallNode 只存 start: [x, z] 和 end: [x, z]，厚度沿左法线双向外扩。平面坐标类型叫 Point2D， 字段是 { x, y }，而这个 y 是世界 Z。 这个命名很坑，但它是原项目的约定，你抄了才能随时对照源码。

④ registry 是命令式路径的地基

sceneRegistry 是一个全局可变的 Map<nodeId, Object3D>， 改它不会触发任何重渲染。M1 你只用它做一件小事：验证点击命中的 mesh 能反查回 node id。 看起来多此一举——直接在 <mesh onClick> 上拿 node.id 不就行了？对，M1 确实就行。但 M3 的拖拽和 M4 的 GeometrySystem 会绕开 React 直接 mutate 这些 Object3D，那时没有 registry 就只能遍历场景图。地基现在打，成本最低。

export const NodeRenderer = ({ nodeId }: { nodeId: AnyNodeId }) => {
  const node = useScene((state) => state.nodes[nodeId])

抄这个文件的四个陷阱

陷阱 1 · 画面完全静止且不报错

千万别抄 frameloop="never"。原项目配 <FrameLimiter fps={50}/> 主动调 invalidate() 控制帧率。 只抄前半句的话，第一帧渲染完就再也不更新，而且没有任何报错。 这是 R3F 新手最难自查的卡点。M1 用默认值，别写这个 prop。

陷阱 2 · 两个相机

原项目的 <Canvas camera={{ position: [50,50,50], fov: 50 }}> 和 <ViewerCamera> 同时存在——前者建了一个相机，后者用 makeDefault 又换掉了它。这是历史遗留的冗余，真正生效的是后者。 你只留 <CameraRig>，别写 camera prop。

陷阱 3 · shadows 的对象形式

shadows={{ type, enabled }} 是给 WebGPU 擦屁股的。源码注释写得很清楚： 切 castShadow 会 dispose 阴影贴图，但 three r184 的 WebGPU node cache 还引用着它，下一帧就是 GPUValidationError，所以改成在 renderer 级别开关。 你用 WebGL + 布尔 shadows，没这个问题。

陷阱 4 · OrbitControls 不在 viewer 里

这是分层，不是遗漏。相机控制器在 packages/editor/src/components/editor/custom-camera-controls.tsx， 属于 editor 层。AGENTS.md 那句 "Editor features are injected into <Viewer> via props and children" 讲的就是它。所以你的 app.tsx 该这么写： 

// src/app/app.tsx
<Viewer mode={viewMode}>
  <OrbitControls makeDefault enableRotate={viewMode === '3d'} />
  <WallTool />
</Viewer>

M1 阶段这看着像脱裤子放屁——控制器明明只有一种用法。但这是第 04 步那道边界考试的 第二题：viewer 提供画布和渲染，app 决定怎么操作它。 等你想把 viewer 单独发包，或者做一个只读展示模式（不要 OrbitControls，要自动旋转）， 这条线就是全部意义。

camera-rig.tsx

// 原项目对应 viewer-camera.tsx，全文 12 行。前两条原样抄，第三条是你独有的。
export function CameraRig({ mode }: { mode: '3d' | 'plan' }) {
  return mode === '3d' ? (
    <PerspectiveCamera  makeDefault fov={50} near={0.1}   far={1000} position={[10, 10, 10]} />
  ) : (
    <OrthographicCamera makeDefault zoom={40} near={-1000} far={1000} position={[0, 40, 0]} />
  )
}
  • makeDefault 两个都要。它把 drei 建的相机写进 R3F 的 state.camera。少了它，画面切了但射线还用旧相机——表现是"点哪都错位"， 而且完全不报错。
  • 正交的 near={-1000}，负数。正交投影没有透视收缩， 近裁面允许在相机后方，这样相机放哪都不裁物体。透视相机写负 near 会直接崩。
  • up 必须显式设成 [0, 0, -1]。见下方陷阱。 drei 的相机组件不接受 up prop，你得拿 ref 在 useLayoutEffect 里写 cam.up.set(0, 0, -1)。顺序有讲究——OrbitControls 挂载时会读 camera.up，所以必须在它之前设好。
three 微练习 · Object3D 与万向锁

相机在正上方看向原点时，默认 up = (0,1,0) 与视线共线， lookAt 退化——画面会随机翻转或直接黑掉。

动手一次：先不设 up，把相机 y 从 40 降到 0 再升回来， 看画面在过零点时怎么跳。理解了再修。

原项目里找不到这个坑的对照。它的正交相机在 [10,10,10]——那是轴测图，不是顶视平面图（它的真·平面图是那套独立 SVG 场景）。你选了"正交顶视当 2D"，相机就落在退化点上。 改了一个前提，原项目就不再是你的答案——这是抄一个项目时最危险的地方。

  divisions       = 200,        // 100/200 = 0.5m 一格，同原项目 cellSize 默认值
  gridColor       = '#d8dcda',
  centerLineColor = '#b4bcb9',
}: {
  size?: number
  divisions?: number
  gridColor?: string
  centerLineColor?: string
}) {
  return (
    <group name="ground">
      {/* 网格线。抬高 1mm，否则和下面的地面共面 → z-fighting */}
      <gridHelper
        args={[size, divisions, centerLineColor, gridColor]}
        position={[0, 0.001, 0]}
        raycast={NEVER_RAYCAST}
      />

      {/* 地面。接收阴影，让 3D 视角下墙有立体感 */}
      <mesh rotation-x={-Math.PI / 2} receiveShadow raycast={NEVER_RAYCAST}>
        <planeGeometry args={[size, size]} />
        <meshStandardMaterial color="#f0f2f1" roughness={1} metalness={0} />
      </mesh>
    </group>
  )
}
  • gridHelper 的 args 顺序是 (size, divisions, colorCenterLine, colorGrid)。 第三个参数是中心两条轴线的颜色，不是"大格子"。three 的 GridHelper 没有 drei <Grid> 那种 cell/section 双层概念——原项目那 322 行是自己写 TSL 着色器实现的。别按 drei 的心智模型传参。
  • 这里全部用声明式，不需要 useMemo + 手动 dispose。 <gridHelper args={...}> 是 R3F 创建的，卸载时它自己收拾。 和第 09 步的 WallRenderer 正好相反——两个样本放在一起看， 比背规则清楚。
  • 那个 1mm。网格线与地面共面 → 深度缓冲精度不够 → 画面上出现随相机移动而游走的闪烁条纹（z-fighting）。抬 1mm，肉眼不可见。 这是 3D 里最常见的视觉 bug，你以后在踢脚线、贴地地毯上还会再遇到。
这里会 debug 掉你一小时

地面和网格都必须不参与拾取——给它们 raycast={() => null}。否则你的墙工具会先命中地面 mesh， 而不是走第 10 步 pointer-plane.ts 的数学解。

症状是：射线数学明明算对了，测试也过，就是点不准，而且误差随相机角度变化。 因为你实际拿到的是 mesh 的表面交点，它和数学平面差一个地面网格的厚度／偏移。

三个组件，一条链，每个只有一个职责和一次订阅：

SceneRenderer      订阅 rootNodeIds（id 数组，引用稳定）  → 只在增删墙时重渲染
  └ NodeRenderer   订阅 nodes[nodeId]（单个节点）         → 只在这堵墙变时重渲染
      └ WallRenderer   不订阅任何东西，纯 props            → 把 WallNode 变成一个 mesh

NodeRenderer 是分发器——拿到节点，看 node.type，决定挂载哪个具体渲染器。M1 只有一个 case，看起来它什么都没干； M4 会变成三个 case，原项目里则进化成查注册表 + React.lazy 的 56 行。

WallRenderer 是具体渲染器——只认识 WallNode，不知道 store 存在，不知道别的类型存在。 这是它能被 props 完全决定、因而好测好换的原因。

// src/viewer/components/wall-renderer.tsx —— 纯组装，全码

export function WallRenderer({ node }: { node: WallNode }) {
  const ref = useRef<THREE.Mesh>(null!)
  useRegistry(node.id, 'wall', ref)

  // ⚠ 依赖写具体字段，不是 [node]。
  //   updateNode 浅合并每次都换 node 引用，写 [node] 等于没有 memo。
  const geometry = useMemo(
    () => buildWallGeometry(node),
    [node.start[0], node.start[1], node.end[0], node.end[1], node.thickness, node.height],
  )

  // 清理函数在 geometry 变化时先跑一次 —— 释放的是**旧的**那个。
  useEffect(() => () => geometry.dispose(), [geometry])

  const { position, rotationY } = useMemo(
    () => wallTransform(node),
    [node.start[0], node.start[1], node.end[0], node.end[1], node.height],
  )

  return (
    <mesh
      ref={ref}
      geometry={geometry}
      position={position}
      rotation-y={rotationY}
      visible={node.visible !== false}
      castShadow
      receiveShadow
    >
      <meshStandardMaterial color="#e8e8e8" roughness={0.9} metalness={0} />
    </mesh>
  )
}
geometry 要手动 dispose，材质不用

这条规则决定你后面所有的内存管理，现在就记死：

  • geometry 是你 new 出来当 prop 传进去的 → R3F 没创建它，不负责销毁 → 你自己 dispose
  • <meshStandardMaterial> 是声明式子元素 → R3F 创建的，卸载时它自己 dispose → 你别管
three 微练习 · dispose 与显存

JS 的 GC 管不到显卡。BufferGeometry 和 Material 在 GPU 上的缓冲区只有 .dispose() 能释放。

动手一次：先故意不写 dispose，画 20 堵墙再全删， 在 DevTools 里看 renderer.info.memory.geometries——数字只涨不跌。 然后补上 dispose 再看一遍。M3 拖拽时几何每帧重建， 这个数字会以每秒 60 的速度涨，几秒钟吃掉几百 MB。

wall-renderer.tsx 有保质期，现在就该知道。 原项目里没有这个文件——墙走的是通用的 ParametricNodeRenderer （98 行，全项目所有参数化节点共用一个）。它的文档注释说得很直白：

Mounts an empty <group>. Registers it with sceneRegistry so <GeometrySystem> can find it and inject children built by def.geometry(node, ctx).

也就是说，三复选框模型走到终点，per-kind 的 renderer 会消失—— 渲染器退化成一个空 group，几何由 <GeometrySystem> 每帧读脏标记、 调 def.geometry() 塞进去。你的 WallRenderer 在 M4 会被这个通用件吃掉，buildWallGeometry 则从 viewer 组件里被拆出来， 变成注册表里的 def.geometry。

现在别提前做。但写这个文件时心里有数： 你真正在写的是 buildWallGeometry，WallRenderer 只是它 M1 阶段的临时外壳。所以几何逻辑一行都别写进组件里。

// src/core/lib/geometry-2d.ts
// ⚠ Point2D.y 是世界 Z。原项目的约定，抄它是为了能对照源码。

export type Point2D = { x: number; y: number }

export const EPSILON = 1e-9

export const sub   = (a: Point2D, b: Point2D): Point2D => ({ x: a.x - b.x, y: a.y - b.y })
export const add   = (a: Point2D, b: Point2D): Point2D => ({ x: a.x + b.x, y: a.y + b.y })
export const scale = (v: Point2D, k: number):  Point2D => ({ x: v.x * k,  y: v.y * k })
export const len   = (v: Point2D): number => Math.hypot(v.x, v.y)

export const midpoint = (a: Point2D, b: Point2D): Point2D =>
  ({ x: (a.x + b.x) / 2, y: (a.y + b.y) / 2 })

export function normalize(v: Point2D): Point2D {
  const l = len(v)
  // 绝不放 NaN 出去 —— NaN 进了 three 的矩阵，画面整个消失且控制台一声不吭。
  if (l < EPSILON) return { x: 0, y: 0 }
  return { x: v.x / l, y: v.y / l }
}

/** 沿 start→end 方向看的左手边法线（单位向量）。
 *  这个方向定死了 M4 门窗的 interior / exterior 语义。现在别改，以后也别改。 */
export function leftNormal(v: Point2D): Point2D {
  return normalize({ x: -v.y, y: v.x })
}

/** 墙的平面轮廓，恰好 4 点，顺序固定：
 *    startLeft → endLeft → endRight → startRight
 *  M2 的斜接会把其中某几个替换成相邻墙的交点，但四个角的名字不变。 */
export function wallFootprint(start: Point2D, end: Point2D, thickness: number): Point2D[] {
  const v = sub(end, start)
  if (len(v) < EPSILON) return []          // 退化墙必须有出口
  const n = scale(leftNormal(v), thickness / 2)
  return [add(start, n), add(end, n), sub(end, n), sub(start, n)]
}

import { useLayoutEffect, type RefObject } from 'react'
// import type —— 编译后整行消失，core 保持零运行时依赖。
import type * as THREE from 'three'
import type { AnyNodeId } from '../schema/types'

// 全局可变单例，不是 React state。改它不触发任何重渲染 —— 这是故意的，
// 也正是 M3 命令式路径（每帧 mutate 但一次都不 setState）的地基。
export const sceneRegistry = {
  nodes:  new Map<AnyNodeId, THREE.Object3D>(),
  byType: {} as Record<string, Set<AnyNodeId>>,
}

export function useRegistry(
  id: AnyNodeId,
  type: string,
  ref: RefObject<THREE.Object3D | null>,
) {
  // useLayoutEffect，不是 useEffect。注册必须在首次绘制前完成，
  // 否则同一帧里跑的 system 查不到对象。原项目源码里专门写了这一句。
  useLayoutEffect(() => {
    const obj = ref.current
    if (!obj) return

    obj.userData.nodeId = id          // 只在这一处写
    sceneRegistry.nodes.set(id, obj)
    ;(sceneRegistry.byType[type] ??= new Set()).add(id)

    return () => {
      sceneRegistry.nodes.delete(id)
      sceneRegistry.byType[type]?.delete(id)
      delete obj.userData.nodeId
    }
  }, [id, type, ref])
}

/** 从命中的 mesh 沿 parent 往上走，找第一个带 nodeId 的对象。
 *  为什么不给每个 mesh 都挂 nodeId？M4 一堵墙会有 N 个子 mesh
 *  （墙体 / 洞口边 / 踢脚线）。向上走一次比维护 N 份冗余便宜。 */
export function nodeIdFromObject(obj: THREE.Object3D | null): AnyNodeId | null {
  let cur: THREE.Object3D | null = obj
  while (cur) {
    const id = cur.userData?.nodeId
    if (typeof id === 'string') return id as AnyNodeId
    cur = cur.parent
  }
  return null
}

type SceneState = {
  // Record 不用 Map：O(1) 查、结构共享便宜、M5 能直接 JSON.stringify。
  nodes: Record<AnyNodeId, AnyNode>

  addNode:    (input: unknown) => AnyNodeId
  updateNode: (id: AnyNodeId, patch: Partial<AnyNode>) => void
  removeNode: (id: AnyNodeId) => void
  getNode:    (id: AnyNodeId) => AnyNode | undefined
}

// 这里不许出现 selectedId。"谁被选中"是编辑器状态 → app 层的 useEditor。
// 它不进存档、不进撤销历史，换个宿主就换套语义。这是 M1 唯一一次考你分层。
export const useScene = create<SceneState>((set, get) => ({
  nodes: {},
  rootNodeIds: [],

  addNode: (input) => {
    // parse 一次同时完成三件事：填 id、填默认值、挡住非法数据。
    // 慢 —— 但 M5 加载旧存档时，这行就是迁移入口。
    const node = AnyNode.parse(input)
    set((s) => ({
      nodes:       { ...s.nodes, [node.id]: node },
      rootNodeIds: [...s.rootNodeIds, node.id],
    }))
    return node.id
  },

  // 浅合并即可。深合并的需求要到 M4 的嵌套配置才出现，别提前做。
  updateNode: (id, patch) => set((s) => {
    const prev = s.nodes[id]
    if (!prev) return s
    return { nodes: { ...s.nodes, [id]: { ...prev, ...patch } as AnyNode } }
  }),

  // 现在只删自己。M5 才处理 children 级联。
  removeNode: (id) => set((s) => {
    if (!s.nodes[id]) return s
    const nodes = { ...s.nodes }
    delete nodes[id]
    return { nodes, rootNodeIds: s.rootNodeIds.filter((n) => n !== id) }
  }),

  getNode: (id) => get().nodes[id],
}))

// src/viewer/lib/wall-geometry.ts
import * as THREE from 'three'
import { len, midpoint, sub, type Point2D } from '../../core/lib/geometry-2d'
import { getWallHeight, getWallThickness, type WallNode } from '../../core/schema/wall'

const toPoint = (t: readonly [number, number]): Point2D => ({ x: t[0], y: t[1] })

export function buildWallGeometry(wall: WallNode): THREE.BufferGeometry {
  const length = len(sub(toPoint(wall.end), toPoint(wall.start)))
  // M1 就用 Box。手搓顶点留到 M2 —— 那时你需要任意四边形轮廓，Box 才真的不够用。
  return new THREE.BoxGeometry(length, getWallHeight(wall), getWallThickness(wall))
}

export function wallTransform(wall: WallNode): {
  position: [number, number, number]
  rotationY: number
} {
  const start = toPoint(wall.start)
  const end   = toPoint(wall.end)
  const c     = midpoint(start, end)

  // 坐标系推导 —— 在纸上画一遍，别背：
  //   Point2D.y ≡ 世界 Z。BoxGeometry 的长边沿局部 +X。
  //   绕 Y 轴正向旋转 θ，把 +X 转到 (cos θ, 0, −sin θ)。
  //   要它对齐方向向量 (dx, dz)/|v| ⟹ θ = atan2(−dz, dx)
  //   自检：墙沿 +Z 时 dx=0, dz>0 ⟹ θ = −π/2 ⟹ +X 转成 (0,0,1) ✓
  //   少一个负号的表现：轴对齐的墙全对，斜墙沿中心线镜像。
  const rotationY = Math.atan2(-(end.y - start.y), end.x - start.x)

  // Box 原点在体心，墙底要贴地 → y = 高度的一半
  return { position: [c.x, getWallHeight(wall) / 2, c.y], rotationY }
}

import * as THREE from 'three'
import type { Point2D } from '../../core/lib/geometry-2d'

const raycaster = new THREE.Raycaster()
const plane     = new THREE.Plane()
const UP        = new THREE.Vector3(0, 1, 0)
// 复用模块级 scratch 是安全的 —— 我们立刻读出 x/z 并返回一个新对象，
// 从不把 scratch 本身交给调用方。这正是可以复用的判据。
const scratch   = new THREE.Vector3()

/** 屏幕 NDC 点 → 地平面上的世界点。
 *  纯数学，不依赖任何实体 mesh，所以永不被遮挡，正交 / 透视都成立。 */
export function screenToGround(
  pointer: THREE.Vector2,   // NDC，[-1,1]。R3F 的 useThree().pointer 已经是这个
  camera: THREE.Camera,
  planeY = 0,
): Point2D | null {
  raycaster.setFromCamera(pointer, camera)
  // ⚠ Plane 第二个参数是「有符号距离常数」，不是高度。
  //   y = h 的平面 ⟹ constant = −h。写成 +h 时墙会画在镜像高度上。
  plane.set(UP, -planeY)
  const hit = raycaster.ray.intersectPlane(plane, scratch)
  if (!hit) return null                // 射线与平面平行（相机水平看）
  return { x: hit.x, y: hit.z }        // ← 世界 Z 落进 Point2D.y
}

      // 自己算 NDC：原生事件先于 R3F 的 state.pointer 更新，读它可能是上一帧的。
      const r = el.getBoundingClientRect()
      ndc.set(
        ((e.clientX - r.left) / r.width)  * 2 - 1,
        -((e.clientY - r.top) / r.height) * 2 + 1,
      )
      const p = screenToGround(ndc, camera)
      if (!p) return

      const start = pendingRef.current
      if (!start) { pendingRef.current = p; return }
      pendingRef.current = null
      // 预览墙**绝不**先 addNode 进 store —— 那是 M3 live-overrides 的活，
      // 提前做会污染撤销历史。
      useScene.getState().addNode({
        type:  'wall',
        start: [start.x, start.y],
        end:   [p.x, p.y],
      })
    }

    const onKeyDown = (e: KeyboardEvent) => {
      if (e.key === 'Escape') pendingRef.current = null
    }

    el.addEventListener('pointerdown', onPointerDown)
    window.addEventListener('keydown', onKeyDown)
    return () => {
      el.removeEventListener('pointerdown', onPointerDown)
      window.removeEventListener('keydown', onKeyDown)
    }
  }, [activeTool, gl, camera])

  return null
}
