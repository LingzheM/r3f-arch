结论

闸门问的是「加 slab 要不要改框架文件」，答案是不要。测量通过，可以写 M6。

后两条是「框架还缺两个一次性能力」，不是「每种类型的固定成本」。 判据很简单：加第四种类型时它们还要不要再改一次？ 不要 → 是一次性能力。要 → 才是 M5 没成立。 这两条都是不要。

换个说法：M5 结束时注册表只有一个用户，而那个用户 （wall）既没有 position，也是唯一可选中的东西。 一个从没有过第二个用户的接口，不可能提前长出第二个用户需要的形状。 这正是 M6 存在的理由——它是 M5 的第一次真实负载测试。

02机制说明

两种节点形状的第一次碰撞：信封 vs 渲染器绑定

结论先说：两条路并存，判据是 schema 里有没有 position

节点 schema 里有 position 字段 → builder 产出局部坐标， ParametricNodeRenderer 用 JSX 绑 <group position>。
没有 position（由点/线/环定义）→ builder 把世界坐标烤进几何，返回信封， 渲染器的 <group> 留在原点。

两条路并存不是失败。规格书自己就允许—— node-definitions.md:185 写的是 position={liveTransform?.position ?? node.position}， ?? 右边取不到时它就是 [0,0,0]， 信封路线正是这个式子的退化情形。但"为什么并存"必须写清楚， 否则 M7 门窗（也有 position）来的时候没人知道该走哪条。

为什么 wall / slab / ceiling 不能走规格书原路

试着给 slab 加一个 position 会怎样。多边形是 [[0,0], [4,0], [4,3], [0,3]]，你得选一个原点——质心？包围盒中心？首点？ 然后把每个顶点减掉它，存成局部坐标。于是：

  • 拖一个顶点 → 质心变了 → 其余三个顶点的局部坐标全要重算， 而它们在世界里根本没动
  • 两块楼板拼在一起 → 它们的顶点在世界里重合， 但在各自局部坐标里是两个不同的数 → 吸附、共边检测全部要先转世界
  • M7 的门要落在墙上、M11 的楼梯要落在楼板上 → 宿主关系全是世界坐标的

这就是"由点定义，几何和位置分不开"的确切含义： 对这类节点，position 是一个派生量，不是一个自变量。 存一个派生量当自变量，就得在每次编辑后维护它的一致性—— 那是 bug 的温床。

为什么 column 必须走规格书原路

反过来，column 的 position 是真自变量：

  • 柱子的形状（半径、高、截面）和它站在哪完全无关
  • 移动柱子 = 改一个三元组，几何一个字节都不用重算
  • M13 做属性面板时，"X / Y / Z"是三个可以直接编辑的数字

import type { Point2D } from './geometry-2d'

/**
 * 鞋带公式。Point2D.y 是世界 Z（D3），所以这是「世界 XZ 平面上的有符号面积」。
 *
 * 符号的含义现在没有消费者 —— M6 不做绕向归一化，因为 THREE.ExtrudeGeometry
 * 自己会把外轮廓转成 CCW（见 §06）。留着导出是因为 M7 挖洞时
 * 洞必须和外轮廓反向，那时判绕向就靠它。
 */
export function signedArea(polygon: readonly Point2D[]): number {
    if (polygon.length < 3) return 0

    let sum = 0
    for (let i = 0; i < polygon.length; i += 1) {
        const p = polygon[i]!
        const q = polygon[(i + 1) % polygon.length]!
        sum += p.x * q.y - q.x * p.y
    }
    return sum / 2
}

/** 面积。工具用它挡住退化多边形（三点共线 / 首尾重合）。 */
export function polygonArea(polygon: readonly Point2D[]): number {
    return Math.abs(signedArea(polygon))
}

import * as THREE from 'three'

/**
 * 把世界 XZ 多边形挤出成 [bottomY, topY] 之间的实体。slab 和 ceiling 共用。
 *
 * 返回的是一个「信封」：root > mesh，mesh 的顶点已经是世界坐标。
 * slab / ceiling 的 schema 里没有 position 字段 —— 它们由点定义，
 * 几何和位置分不开，所以不走规格书的「builder 出局部坐标 + 渲染器绑 position」
 * 那条路。判据和理由见 §02。
 *
 * 坐标链和 wall/geometry.ts 完全一致：
 *   shape 空间 (x, y) --ExtrudeGeometry(depth)--> (x, y, w)
 *   --rotateX(-π/2)--> 世界 (x, w, -y)
 * 所以要让世界 Z = p.y，shape 里必须写 -p.y。这个负号省不得（§04 第 05 步）。
 */
export function buildPolygonPrism({
    polygon,
    bottomY,
    topY,
    color,
    name,
}: {
    polygon: readonly (readonly [number, number])[]
    bottomY: number
    topY: number
    color: string
    name: string
}): THREE.Object3D {
    const root = new THREE.Group()

    const height = topY - bottomY
    // 和 buildWallGeometry 的 worldFootprint.length < 3 是同一条防线。
    if (polygon.length < 3 || height <= 0) return root

    const shape = new THREE.Shape()
    shape.moveTo(polygon[0]![0], -polygon[0]![1])
    for (let i = 1; i < polygon.length; i += 1) {
        shape.lineTo(polygon[i]![0], -polygon[i]![1])
    }
    shape.closePath()

    const geometry = new THREE.ExtrudeGeometry(shape, { depth: height, bevelEnabled: false })
    geometry.rotateX(-Math.PI / 2)
    geometry.translate(0, bottomY, 0)

    const material = new THREE.MeshStandardMaterial({ color, roughness: 0.9, metalness: 0 })

    const mesh = new THREE.Mesh(geometry, material)
    mesh.name = name
    mesh.castShadow = true
    mesh.receiveShadow = true

    root.add(mesh)
    return root
}

export function buildColumnGeometry(
    node: ColumnNode,
    _ctx: GeometryContext,
    appearance: NodeAppearance,
): THREE.Object3D {

    const height = getColumnHeight(node)

    const geometry =
        node.crossSection === 'round'
            ? new THREE.CylinderGeometry(
                  getColumnRadius(node), getColumnRadius(node), height, RADIAL_SEGMENTS,
              )
            : new THREE.BoxGeometry(getColumnWidth(node), height, getColumnDepth(node))

        color: appearance.selected ? COLUMN_SELECTED_COLOR : COLUMN_COLOR,
        roughness: 0.85,
        metalness: 0,

    mesh.name = 'column-body'
    mesh.castShadow = true
    mesh.receiveShadow = true

    root.add(mesh)

import { polygonArea } from '../../../core/lib/polygon-2d'

// 点回起点附近就闭合。0.25m 相对网格步长 0.1m 足够宽容，
// 又不至于在画很小的板时误判。
export const CLOSE_RADIUS = 0.25

// 挡退化多边形：三点共线、所有点重合。
// 放过去的话 ExtrudeGeometry 会生成 NaN 法线，画面上是一块黑斑。
export const MIN_POLYGON_AREA = 1e-4

/** 这一次点击是不是「闭合」而不是「加一个顶点」。 */
export function isClosingClick(points: readonly Point2D[], p: Point2D): boolean {
    // ⚠ 必须先判点数：第二个点落在第一个点附近是合法的（画很小的板），
    //   不该被当成闭合。
    if (points.length < 3) return false
    const first = points[0]!
    return Math.hypot(p.x - first.x, p.y - first.y) <= CLOSE_RADIUS
}

/** 这个草稿能不能变成一个真节点。 */
export function isCommittablePolygon(points: readonly Point2D[]): boolean {
    return points.length >= 3 && polygonArea(points) > MIN_POLYGON_AREA
}

/** Point2D[] → schema 要的 [x, z][]。 */
export function toPolygonTuples(points: readonly Point2D[]): [number, number][] {
    return points.map((p) => [p.x, p.y])
}

    isCommittablePolygon,
    toPolygonTuples,
} from "../lib/interaction/polygon-draft"

const PREVIEW_Y = 0.02

// Line2 的 setPositions 要求点数不变，所以预览用定长缓冲。
// 超过 62 个顶点预览线会截断（数据不会）—— §06 记了，到期 M13。
const MAX_PREVIEW_POINTS = 64
const PREVIEW_INIT: [number, number, number][] = Array.from(
    { length: MAX_PREVIEW_POINTS },
    () => [0, PREVIEW_Y, 0] as [number, number, number],
)

/**
 * slab 和 ceiling 共用的「点击成环」工具。
 *
 * ⚠ 两个实例同时挂载（<PolygonTool tool="slab"/> 和 tool="ceiling"），
 *   靠 activeTool === tool 各自失活。所以每次读 scope 都必须【连 tool 一起判】，
 *   否则两个实例会读到对方的草稿。见 §02 最后那个 trap。
 *
 * 不走事件总线 —— D15：「工具在自己的 scope 活跃期间直接监听 canvas DOM」。
 */
export function PolygonTool({ tool }: { tool: PolygonToolKind }) {
    const activeTool = useEditor((s) => s.activeTool)
    const { gl, camera } = useThree()

    const cursorRef = useRef<Point2D | null>(null)
    const active = activeTool === tool

    useEffect(() => {
        if (!active) return
        useInteractionScope.getState().begin({ kind: 'drafting', tool, points: [] })
        return () => {
            useInteractionScope.getState().endIf((s) => s.kind === 'drafting' && s.tool === tool)
            cursorRef.current = null
        }
    }, [active, tool])

    useEffect(() => {
        if (!active) return
        const el = gl.domElement

        const currentPoints = (): readonly Point2D[] => {
            const scope = getScope()
            return scope.kind === 'drafting' && scope.tool === tool ? scope.points : []
        }

        const reset = () => {
            useInteractionScope.getState().update('drafting', { points: [] })
            cursorRef.current = null
        }

        const commit = () => {
            const points = currentPoints()
            if (!isCommittablePolygon(points)) return

            // 工具对类型一无所知：只写 type + polygon，
            // 厚度 / 标高 / 高度全部由 zod 的 .default() 填。
            // 所以加 ceiling 的工具成本是 0 行（§02 末尾）。
            useScene.getState().addNode({ type: tool, polygon: toPolygonTuples(points) })
            reset()
        }

        const onPointerUp = (e: PointerEvent) => {
            if (e.button !== 0) return
            if (!isClickGesture(e)) return

            const raw = eventToGround(e, el, camera)
            if (!raw) return
            const point = snapToGrid(raw)

            const points = currentPoints()
            if (isClosingClick(points, point)) {
                commit()
                return
            }
            useInteractionScope.getState().update('drafting', { points: [...points, point] })
        }

        const onPointerMove = (e: PointerEvent) => {
            cursorRef.current = eventToGround(e, el, camera)
        }

        const onKeyDown = (e: KeyboardEvent) => {
            if (e.key === 'Escape') reset()
            if (e.key === 'Enter') {
                e.preventDefault()
                commit()
            }
        }

        el.addEventListener('pointerup', onPointerUp)
        el.addEventListener('pointermove', onPointerMove)
        window.addEventListener('keydown', onKeyDown)

        return () => {
            el.removeEventListener('pointerup', onPointerUp)
            el.removeEventListener('pointermove', onPointerMove)
            window.removeEventListener('keydown', onKeyDown)
        }
    }, [active, tool, gl, camera])

    if (!active) return null
    return <PolygonDraftPreview tool={tool} cursorRef={cursorRef} />
}

function PolygonDraftPreview({
    tool,
    cursorRef,
}: {
    tool: PolygonToolKind
    cursorRef: RefObject<Point2D | null>
}) {
    const lineRef = useRef<ComponentRef<typeof Line>>(null)
    const bufferRef = useRef<number[]>(new Array(MAX_PREVIEW_POINTS * 3).fill(0))

    //   drei 的 Line 把未解构的 props 同时铺到 line2 和 lineMaterial 上，

        if (lineRef.current) lineRef.current.visible = false
    }, [])

        const line = lineRef.current
        if (!line) return

        const scope = getScope()
        const points = scope.kind === 'drafting' && scope.tool === tool ? scope.points : []
        const cursor = cursorRef.current

        if (points.length === 0 || !cursor) {
            line.visible = false
            return
        }

        // 已落的点 → 光标 → 回到起点（闭合提示）
        const path = [...points, cursor, points[0]!].slice(0, MAX_PREVIEW_POINTS)
        const buffer = bufferRef.current

            const q = path[i]!
            buffer[i * 3] = q.x
            buffer[i * 3 + 1] = PREVIEW_Y
            buffer[i * 3 + 2] = q.y
        }
        // 余量用最后一个点填满 —— 长度为零的线段不产生可见像素。
        const last = path[path.length - 1]!
        for (let i = path.length; i < MAX_PREVIEW_POINTS; i += 1) {
            buffer[i * 3] = last.x
            buffer[i * 3 + 1] = PREVIEW_Y
            buffer[i * 3 + 2] = last.y
        }

        line.visible = true
        line.geometry.setPositions(buffer)
        line.computeLineDistances()
    })

    return (
        <Line
            ref={lineRef}
            points={PREVIEW_INIT}
            color="#0b6e5f"
            lineWidth={2}
            dashed
            dashScale={20}
        />
    )

        // ⚠ 依赖 registerAllNodes() 已经跑过。它在 Viewer 的 useState 初始化器
        //   （渲染期）里跑，而 React 保证父组件渲染早于子组件 effect ——
        //   所以这里拿到的注册表一定是满的。register.ts 顶上有对应的注释。
        const clickKeys = [...nodeRegistry.entries()].map(
            ([kind]) => `${kind}:click` as NodeEventKey,
        )

        for (const key of clickKeys) emitter.on(key, onNodeClick)
        emitter.on('grid:click', onGridClick)

        return () => {
            for (const key of clickKeys) emitter.off(key, onNodeClick)
            emitter.off('grid:click', onGridClick)
        }
    }, [])

    return null
}
