M4 拖动、撤销、脏传播

墙终于能动了：整墙拖、端点拖、吸附到已有端点、Delete 删除、Ctrl+Z 撤销。 一次拖拽是一条历史，不是六十条。 拖第 37 堵墙的时候，只有它和它的邻居重建几何，另外 98 堵一动不动。

M3 建立了「此刻谁拥有指针」。M4 建立的是「此刻谁拥有真相」—— 拖拽中的墙在哪，主 store 不知道也不该知道。这一条决定了后面所有拖拽型工具的写法。

01为什么不能直接改 store

最朴素的写法会同时踩三个坑

拖一堵墙，最直觉的实现是这样：

// 每次 pointermove：
useScene.getState().updateNode(wallId, { start: [x1, y1], end: [x2, y2] })

这一行在你现在的代码里会同时引爆三样东西：

坑为什么你会看到
历史被打成碎片 zundo 记录每一次 set 拖 1 秒 = 60 条 undo，Ctrl+Z 按到手酸才回到原位
全场景重算 useLevelMiters 依赖整个 nodes 对象，updateNode 换掉它的引用 100 堵墙 × 60 帧 = 每秒 6000 次 ExtrudeGeometry
中途状态进了文档 主 store 就是文档本身 M9 的自动保存会把「拖到一半」的位置存进档

三个坑的共同点：主 store 是「文档」，而拖拽中的位置不是文档，是「意图」。 把意图写进文档，文档就得替它承担撤销、持久化、脏传播三份本不该承担的责任。

M4 的全部设计都从这一句推出来：

主 store  = 已提交的文档      ← 进历史、进存档、驱动脏集
live 覆盖 = 未提交的意图      ← 不进历史、不进存档、每帧可变
Object3D  = 当前画面          ← 连 React 都不必知道它变了

渲染读的是「文档 ⊕ 覆盖」，不是文档。
effectiveNode(node) = { ...node, ...override(node.id) }
ROADMAP 里那句话需要当场修正

ROADMAP.md 的 M4 条目写着「拖拽中 useFrame 直接 mutate Object3D.position，一次都不 setState」。 这句话对墙不成立。

直接 mutate Object3D.position 只对刚体有效——家具、柱子， 形状不随位置变。墙不是刚体。墙动一寸，它和邻墙的斜接角全变， 几何顶点必须重新生成。你只 mutate 了 position，画面上得到的是一堵歪着插进邻墙里的墙。

对照仓库自己就是这么分的：packages/nodes/src/wall/move-tool.tsx 走 useLiveNodeOverrides（一个 zustand store，会 setState）， 而 useLiveTransforms + useFrame 那条路留给 item 那种真刚体。M4 两条路都建，但用在不同地方——见 §02 D。

02四个机制，各关一个缺陷

互相独立，可以分四天做，每天结束都能跑

A · live 覆盖层 —— 关掉「历史被打成碎片」

一个模块级 zustand store，Map<nodeId, Partial<AnyNode>>。 拖拽期间工具往里写，渲染层读「文档 ⊕ 覆盖」。松手时清空覆盖、写一次主 store。

它仍然是 setState——每帧一次 zustand 通知。这没关系： 通知只惊动订阅了覆盖的那几个组件，而且它不在 zundo 的包裹范围内 （zundo 只包 useScene），所以历史是干净的。 三个坑里最狠的那个由它单独关掉。

B · 脏集 + 邻接 + miter 缓存 —— 关掉「全场景重算」

三段接力，缺一段都不生效：

  1. useScene.dirtyNodes: Set<AnyNodeId> —— 谁变了。
  2. getAdjacentWallIds(walls, dirtyIds) —— 谁因为它而变了（共端点 + T 接两个方向）。
  3. getCachedLevelMiters(walls) —— miter 解只在输入真变了时重算。

第 3 段的判据是逐字段精确比较，不是哈希、也不是引用比较。 对照仓库在 level-miter-cache.ts 里专门写了理由：

"The comparison is exact (no hashing): a stale hit would silently render wrong joints, and 7 numeric compares × N walls is microseconds — far cheaper than the risk."

引用比较为什么不行：你的 updateNode 每次都 { ...prev, ...patch } 造新对象，哪怕改的只是 name。 用引用比较，改一次名字就重算全场斜接。

这一条推翻 STATE.md 的一项欠账

STATE.md 把「交点检测 O(交点×墙)，无空间网格」标成 M4 到期。 M4 不建空间网格，改期到 M8 之后。

理由是成本结构和当初设想的不一样。calculateLevelMiters 是纯 2D 数值运算， 100 堵墙一趟约 2 万次 pointOnSegment，量级 1ms； 而单堵墙的一次 ExtrudeGeometry 就要几百微秒，100 堵是几十毫秒。 真正卡帧的是几何重建，不是交点检测。

先做缓存（idle 帧成本归零）+ 邻接脏集（几何重建从 100 堵降到 3 堵）， 这两条把帧时间从几十毫秒压到一位数。 空间网格是在这之后才成为瓶颈的东西，现在做属于优化未测量的代码。

缺陷清单里这一条不删，只改期，并且把「什么时候该做」写成可判定的条件： 单层墙数 > 300 且 miter 计算在 profile 里稳定超过 3ms。 到不了这个条件就一直不做。

C · zundo + pause 租约 —— 让一次拖拽变成一条历史

有了 A 仍然需要 C。A 只保证「拖拽中不写主 store」， 而松手时那一次写本身还可能被拆成多条： 拖一堵墙会连带更新邻墙的端点，那是好几次 updateNode。

两件工具：

  • pause 租约：拖拽开始时 acquireSceneHistoryPause()， 拿到一个 release 闭包。租约可重入——深度归零才真的 resume。 为什么不是一个布尔：两个东西同时暂停历史时，先结束的那个不能把后一个的暂停一起关掉。
  • 事务：runAsSingleHistoryStep(fn)，跑完把 pastStates 里新增的 N 条截成 1 条。
顺序反了会丢掉一步撤销

提交时必须是 先 resume 再写，不能 先写再 resume。 历史暂停期间的写入根本不产生 pastState—— 你写完再 resume，那条改动就永远撤不回来了。

对照仓库把这三行单独抽成了一个 14 行的文件 （editor/src/components/editor/handles/handle-drag-history.ts）， 只为了让顺序无处可错：resumeHistory() → runAsSingleHistoryStep(() => commit(patch))。你也这么做。

D · 命令式预览 —— 关掉「橡皮筋每帧重渲染」

这才是 ROADMAP 那句「一次都不 setState」的真正落点。 橡皮筋是纯呈现，没有任何别的模块需要读它的值——于是 pointermove 只写 ref， useFrame 每帧把 ref 的值刷进 line 的顶点。 React 全程不知道光标动过。

判据可以直接搬 M3 §06 那条：「有没有第二个读者」。 没有读者的值就不该进 store——进了就要付出每帧一次订阅通知的代价， 换来的只是「能在 DevTools 里看见它」。

两个当场会咬人的地方

① create<T>()(...) 的双层调用不能省。 你现在写的是 create<SceneState>((set, get) => ...)。 套上 middleware 之后必须换成柯里化形式，否则 TS 推不出中间件叠加后的 store 类型， useScene.temporal 会不存在。

② partialize 只能进 nodes / rootNodeIds。 把 dirtyNodes（第 05 步要加）圈进去的话， 撤销会把脏集一起回滚——你撤销完，几何不重建，画面停在撤销前。 脏集是「谁需要重算」的当下事实，不是文档的一部分。

equality 用语义比较（递归比字段）而不是 Object.is： updateNode 每次造新对象，引用相等永远为假， 于是「拖回原位」也会记一条历史。对照仓库的 areSceneSnapshotsEqual / areSemanticValuesEqual （core/src/store/history-control.ts:90-123）可以直接改写，30 行。

hint —— 租约：

  • 模块级 Set<symbol> 存租约，不是一个计数器。 size === 0 时才 temporal.getState().resume()。
  • 返回的闭包里放一个 let released = false 守卫。 React 18 严格模式的双次 effect 清理会 release 两次，没有守卫就提前 resume 了。
  • 为什么 symbol 不是数字：数字计数器无法诊断泄漏。 symbol 集合可以在开发模式下打印出「谁还没还」。

hint —— 事务：

  • 记下 run() 前的 pastStates，跑完再读一次。
  • 新增了 N > 1 条 ⟹ 只保留第一条（第一条的 before 才是真起点）。
  • 新增了 N 条但语义上前后相等 ⟹ 全部丢弃（拖回原位不该占一条历史）。
  • 不能假设「新增的都在数组尾部」——limit: 50 会从头部截断。对照仓库为此写了 retainedPastStateCount（history-control.ts:236）， 从前往后找最长的公共后缀。15 行，照抄。
这一步必须写测试，而且要在接 UI 之前跑绿

history-control.test.ts 至少四条： 重入（拿两张租约，还一张，历史仍暂停）、 幂等（同一张还两次，深度不变负）、 N 条截成 1 条、 空操作不占历史。 这是纯逻辑，可以在 Node 里裸跑（D11）。 等你在浏览器里发现「Ctrl+Z 少撤一步」再来查，涉及的文件会有五个。

三类邻接，一个都不能漏：

漏它的原因很自然：直觉上「脏的是主墙，主墙动了，找它碰到了谁」。 但 T 接是不对称的——撞人的和被撞的，端点被切的是撞人的那一方， 而拖动的往往是被撞的那一方。方向必须双查。 对照仓库 wall-mitering.ts:497-529 三段并列，注释里明确标了 "Check reverse T-junction"。

测试（wall-adjacency.test.ts）：L 型共端点、 T 型两个方向各一条、不相邻的墙不在结果里（这条最重要—— 邻接函数返回全集也能让画面正确，只是性能优化白做了， 而画面正确会让你以为它对）。

M3 的 update() 签名到这里会开始骗人

你现在的写法（use-interaction-scope.ts:17-23）是：

update: (patch: Partial<ActiveInteractionScope>) => ...
  if ('kind' in patch && patch.kind !== state.scope.kind) return state
  return { scope: { ...state.scope, ...patch } as InteractionScope }

只有一个活跃变体时它是安全的。加到三个之后， Partial<A | B | C> 会分配成 Partial<A> | Partial<B> | Partial<C>， 而不带 kind 的 patch 绕过了那道守卫： 在 drafting 里调 update({ nodeId }) 完全合法， 你会得到一个 { kind: 'drafting', points: [...], nodeId: ... } ——判别联合里不存在的形状。那句 as InteractionScope 把它盖住了。

改成把 kind 提成第一个必填参数： 

update: <K extends ActiveInteractionScope['kind']>(
  kind: K,
  patch: Partial<Extract<InteractionScope, { kind: K }>>,
) => void

调用方从 update({ points: [p] }) 变成 update('drafting', { points: [p] })——多打九个字符， 换来「patch 的字段必须属于那个变体」由编译器保证， 而且 kind 不匹配时静默 no-op 的语义变成显式的。 这是 M3 方案的一处修正，不是新增功能；改动只在两个文件里。

selectionEnabled 一个字都不用改——它判的是 kind === 'idle'，加多少变体都还是那句话。 这就是当初选判别联合而不是布尔标志的全部回报。

import { useContext, useEffect, useMemo, useRef } from "react";
import type { WallNode } from "../../core/schema/wall";
import type * as THREE from 'three'
import { useRegistry } from "../../core/registry/scene-registry";
import { buildWallGeometry, wallTransform } from "../lib/wall-geometry";
import { MiterContext, SelectionContext } from "./scene-context";
import { useNodeEvents } from "../hooks/use-node-events";
import { useEffectiveNode } from "../hooks/use-effective-node";


const WALL_COLOR = '#e8e8e8'
const WALL_SELECTED_COLOR = '#7dd3c0'

export function WallRenderer({ node: documentNode }: { node: WallNode }) {
    // 文档 ⊕ 覆盖。拖拽期间 documentNode 一动不动，变的是覆盖。
    const node = useEffectiveNode(documentNode)

    const ref = useRef<THREE.Mesh>(null)
    useRegistry(node.id, 'wall', ref)

    const miter = useContext(MiterContext)

    const selectId = useContext(SelectionContext)
    const isSelected = selectId === node.id

    // ⚠ 这个 events 是 useNodeEvents 的返回值。
    //   不要让 IDE 自动导入 @react-three/fiber 的同名导出 —— 那是
    //   createPointerEvents 函数，展开得到零个属性，而且一处都不报错。
    const events = useNodeEvents(node, 'wall')

    const geometry = useMemo(
        () => buildWallGeometry(node, miter),
        [node.start[0], node.start[1], node.end[0], node.end[1], node.thickness, node.height, miter],
    )

    useEffect(() => () => geometry.dispose(), [geometry])

    const { position, rotationY } = useMemo(
        () => wallTransform(node),
        [node.start[0], node.start[1], node.end[0], node.end[1]],
    )

    return (
        <mesh
            ref={ref}
            geometry={geometry}
            position={position}
            rotation-y={rotationY}
            visible={node.visible !== false}
            castShadow
            receiveShadow
            {...events}
        >
            <meshStandardMaterial
                color={isSelected ? WALL_SELECTED_COLOR : WALL_COLOR}
                roughness={0.9}

// 语义相等
//
// 为什么不是 Object.is：updateNode 每次都 { ...prev, ...patch } 造新对象，
// 引用相等永远为假 —— 于是「把墙拖回原位」也会记一条历史。

export function areSemanticValuesEqual(left: unknown, right: unknown): boolean {
  if (Object.is(left, right)) return true
  if (typeof left !== typeof right || left === null || right === null) return false

  if (Array.isArray(left) || Array.isArray(right)) {
    if (!(Array.isArray(left) && Array.isArray(right)) || left.length !== right.length) return false
    return left.every((value, index) => areSemanticValuesEqual(value, right[index]))
  }

  if (typeof left !== 'object' || typeof right !== 'object') return false

  const l = left as Record<string, unknown>
  const r = right as Record<string, unknown>
  const lKeys = Object.keys(l)
  if (lKeys.length !== Object.keys(r).length) return false

  for (const key of lKeys) {
    if (!(key in r) || !areSemanticValuesEqual(l[key], r[key])) return false
  }
  return true
}

/**
 * 拿一张暂停租约，返回归还闭包。

 * 用 Set<symbol> 而不是一个计数器：计数器泄漏之后你只知道「还差 2 张」，
 * 不知道差的是谁；symbol 集合在开发时可以打印出未归还的租约。
 */
export function acquireSceneHistoryPause(store: PausableStore): () => void {
  if (pauseLeases.size === 0) store.temporal.getState().pause()

  const lease = Symbol('scene-history-pause')
  pauseLeases.add(lease)

  // React 严格模式的双次 effect 清理会 release 两次。没有这个守卫，
  // 第二次 release 会在另一张租约还没还的时候提前 resume。
  let released = false
  return () => {
    if (released) return
    released = true
    pauseLeases.delete(lease)
    if (pauseLeases.size === 0) store.temporal.getState().resume()
  }
}

/** 兜底：丢弃全部租约并恢复记录。只在测试与编辑器整体重置时调。 */
export function resetSceneHistoryPause(store: PausableStore): void {
  const hadLeases = pauseLeases.size > 0
  pauseLeases.clear()
  if (hadLeases) store.temporal.getState().resume()
}

// 事务：把 N 条历史截成 1 条
// ─────────────────────────────────────────────────────────────

type HistoryStore<TPast> = {
  temporal: {
    getState(): { pastStates: TPast[] }
    setState(partial: { pastStates: TPast[] }): void
  }
}

/**
 * `before` 里有多少条在 `after` 里原样保留了下来。
 *
 * 不能假设「新增的都在尾部」：`limit` 到顶时 zundo 会从**头部** shift 掉最老的一条，
 * 于是 after 可能不比 before 长，却仍然是「多了一条」。
 * 从前往后找最长的公共后缀才对。
 */
function retainedPastStateCount<TPast>(before: readonly TPast[], after: readonly TPast[]): number {
  for (let start = 0; start < before.length; start += 1) {
    const retained = before.length - start
    if (retained > after.length) continue

    let matches = true
    for (let index = 0; index < retained; index += 1) {
      if (before[start + index] !== after[index]) {
        matches = false
        break
      }
    }
    if (matches) return retained
  }
  return 0
}

/**
 * 跑 `run()`，把它产生的 N 条历史截成 1 条（保留最早的那条 —— 它的 before 才是真起点）。
 *
 * N === 0 的情况不用管：zundo 的 `equality` 已经把语义空操作挡在门外了。
 */
export function runAsSingleSceneHistoryStep<TPast, TResult>(
  store: HistoryStore<TPast>,
  run: () => TResult,
): TResult {
  // 必须复制。zundo 的 _handleSet 在 limit 到顶时对同一个数组做 shift()，
  // 直接持有引用的话，你「之前」的那份快照会被就地改掉。
  const before = [...store.temporal.getState().pastStates]

  const result = run()

  const after = store.temporal.getState().pastStates
  const retained = retainedPastStateCount(before, after)
  const added = after.length - retained

  if (added > 1) {
    const firstAdded = after[retained]
    if (firstAdded !== undefined) {
      store.temporal.setState({ pastStates: [...after.slice(0, retained), firstAdded] })
    }
  }

  return result
}

type SceneState = {
    nodes: Record<AnyNodeId, AnyNode>
    rootNodeIds: AnyNodeId[]

    /**
     * 谁的几何需要重建。**故意是可变的 Set，不参与 set()。**
     * 它每帧被填满又清空，走 zustand 通知等于每帧唤醒所有订阅者，
     * 而它的消费者本来就是主动读（useMemo，M5 之后是 useFrame）。
     */
    dirtyNodes: Set<AnyNodeId>

    addNode: (input: unknown) => AnyNodeId
    updateNode: (id: AnyNodeId, patch:Partial<AnyNode>) => void
    removeNode: (id: AnyNodeId) => void
    getNode: (id: AnyNodeId) => AnyNode | undefined

    markDirty: (id: AnyNodeId) => void
    clearDirty: (id: AnyNodeId) => void
    markAllDirty: () => void
}

// create<T>()(...) 的双层调用不能省：套上中间件之后必须用柯里化形式，
// 否则 TS 推不出叠加后的 store 类型，useScene.temporal 会不存在。
export const useScene = create<SceneState>()(
  temporal(
    (set, get) =>({
    nodes: {},
    rootNodeIds: [],
    dirtyNodes: new Set<AnyNodeId>(),

    addNode: (input) => {
        // parse 一次同时完成三件事：填 id，填默认值，挡住非法数据。
        const node = AnyNode.parse(input)
        set((s) => ({
            nodes: { ...s.nodes, [node.id]: node },
            rootNodeIds: [...s.rootNodeIds, node.id],
        }))
        get().markDirty(node.id)
        return node.id
    },

    updateNode: (id, patch) => {
        set((s) => {
            const prev = s.nodes[id]
            if (!prev) return s
            return { nodes: { ...s.nodes, [id]: { ...prev, ...patch } as AnyNode } }
        })
        if (get().nodes[id]) get().markDirty(id)
    },

    removeNode: (id) => {
        set((s) => {
            if (!s.nodes[id]) return s
            const nodes = { ...s.nodes }
            delete nodes[id]
            return { nodes, rootNodeIds: s.rootNodeIds.filter((n) => n !== id) }
        })
        get().clearDirty(id)
    },

    getNode: (id) => get().nodes[id],

    markDirty: (id) => { get().dirtyNodes.add(id) },
    clearDirty: (id) => { get().dirtyNodes.delete(id) },

    // 撤销 / 重做之后调：文档整体跳变，谁变了无从增量推导。
    markAllDirty: () => {
        const dirty = get().dirtyNodes
        for (const id of Object.keys(get().nodes) as AnyNodeId[]) dirty.add(id)
    },
    }),
    {
      // 只圈文档。把 dirtyNodes 圈进来的话，撤销会把脏集一起回滚 ——
      // 你撤销完，几何不重建，画面停在撤销前。
      partialize: (s): SceneSnapshot => ({ nodes: s.nodes, rootNodeIds: s.rootNodeIds }),
      equality: (past, current) => areSceneSnapshotsEqual(past, current),
      limit: 50,
    },
  ),
)

import { useScene } from "../../core/store/use-scene";

import { getScope } from "../store/use-interaction-scope";

export function useHistoryShortcuts(): void {
    useEffect(() => {
        const onKeyDown = (e: KeyboardEvent) => {
            if (isTypingTarget(e.target)) return

            // 交互进行中不响应 —— 和 selectionEnabled 同一条铁律。
            // 拖拽中按 Ctrl+Z 该做的是取消拖拽（drag-session 的 Esc 管这个），

            const key = e.key.toLowerCase()

            if (mod && key === 'z' && !e.shiftKey) {
                e.preventDefault()
                useScene.temporal.getState().undo()
                afterHistoryJump()
                return
            }

            if (mod && ((key === 'z' && e.shiftKey) || key === 'y')) {
                e.preventDefault()
                useScene.temporal.getState().redo()
                afterHistoryJump()
                return
            }

            if (key === 'delete' || key === 'backspace') {
                const id = useEditor.getState().selectId
                if (!id) return
                e.preventDefault()

                // 现在 removeNode 只有一次 set，包不包事务都是一条历史。

                runAsSingleSceneHistoryStep(useScene, () => {
                    useScene.getState().removeNode(id)
                })
                useEditor.getState().select(null)
            }
        }

        window.addEventListener('keydown', onKeyDown)
        return () => window.removeEventListener('keydown', onKeyDown)
    }, [])
}

    const id = useEditor.getState().selectId
    if (id && !useScene.getState().nodes[id]) useEditor.getState().select(null)
}

    if (target.isContentEditable) return true
    return target.tagName === 'INPUT' || target.tagName === 'TEXTAREA' || target.tagName === 'SELECT'

type LiveOverrideState = {
  overrides: Map<AnyNodeId, NodeOverride>
  set: (id: AnyNodeId, values: NodeOverride) => void
  setMany: (entries: ReadonlyArray<readonly [AnyNodeId, NodeOverride]>) => void
  clear: (id: AnyNodeId) => void
  clearAll: () => void

export const useLiveOverrides = create<LiveOverrideState>((set, get) => ({
  overrides: new Map(),

  // 每次都换 Map 引用。原地 .set 不换引用，zustand 的默认相等判断
  // 会认为什么都没变，订阅者收不到通知。
  set: (id, values) =>
    set((state) => {
      const next = new Map(state.overrides)
      next.set(id, { ...next.get(id), ...values })
      return { overrides: next }
    }),

  // 不是可选优化。拖一堵墙会连带更新 2–4 堵邻墙；逐个 set 是 N 次 Map 克隆
  // + N 次通知，useLevelMiters 会在一帧内重算 N 次斜接，而且中间那几次
  // 算的是「主墙已移动、邻墙还没动」的自相矛盾状态。
  setMany: (entries) =>
    set((state) => {
      if (entries.length === 0) return state
      const next = new Map(state.overrides)
      for (const [id, values] of entries) next.set(id, { ...next.get(id), ...values })
      return { overrides: next }
    }),

  clear: (id) =>
    set((state) => {
      if (!state.overrides.has(id)) return state
      const next = new Map(state.overrides)
      next.delete(id)
      return { overrides: next }
    }),

  clearAll: () => {
    if (get().overrides.size === 0) return
    set({ overrides: new Map() })
  },
}))

 * 文档 ⊕ 覆盖。没有覆盖时原样返回入参，调用方不必再判一次。
 *
 * 用 getState() 读而不是做成 hook —— 它要能在 useFrame 和裸事件回调里调用。
 * 需要订阅的地方用 viewer/hooks/use-effective-node.ts。
 */

  const override = useLiveOverrides.getState().overrides.get(node.id)
  if (!override) return node
  return { ...node, ...override } as T
}

    const dirty = byId.get(dirtyId)
    if (!dirty) continue

    const dirtyStart = wallStart(dirty)
    const dirtyEnd = wallEnd(dirty)
    const dirtyStartKey = quantizeKey(dirtyStart, JUNCTION_TOLERANCE)
    const dirtyEndKey = quantizeKey(dirtyEnd, JUNCTION_TOLERANCE)

    for (const wall of walls) {
      if (wall.id === dirtyId) continue
      if (dirtyWallIds.has(wall.id)) continue
      if (adjacent.has(wall.id)) continue

      const start = wallStart(wall)
      const end = wallEnd(wall)

      // ① 共端点
      const startKey = quantizeKey(start, JUNCTION_TOLERANCE)
      const endKey = quantizeKey(end, JUNCTION_TOLERANCE)
      if (
        startKey === dirtyStartKey ||
        startKey === dirtyEndKey ||
        endKey === dirtyStartKey ||
        endKey === dirtyEndKey
      ) {
        adjacent.add(wall.id)
        continue
      }

      // ② T 接：脏墙的端点落在别人身上
      if (
        pointOnSegment(dirtyStart, start, end, JUNCTION_TOLERANCE) ||
        pointOnSegment(dirtyEnd, start, end, JUNCTION_TOLERANCE)
      ) {
        adjacent.add(wall.id)
        continue
      }

      // ③ 反向 T 接：别人的端点落在脏墙身上。
      //    T 接是不对称的 —— 端点被切的是「撞人」的那一方，
      //    而你拖动的往往是「被撞」的那一方。方向必须双查。
      if (
        pointOnSegment(start, dirtyStart, dirtyEnd, JUNCTION_TOLERANCE) ||
        pointOnSegment(end, dirtyStart, dirtyEnd, JUNCTION_TOLERANCE)
      ) {
        adjacent.add(wall.id)
      }
    }
  }

  return adjacent
}

/** 脏墙 ∪ 邻墙 —— 「这一次改动必须重建几何的全集」。 */
export function getWallRebuildSet(
  walls: readonly WallNode[],
  dirtyWallIds: ReadonlySet<AnyNodeId>,
): Set<AnyNodeId> {
  const all = getAdjacentWallIds(walls, dirtyWallIds)
  for (const id of dirtyWallIds) all.add(id)
  return all
}

/**
 * 端点共享关系：`wall` 的哪一端贴在 `at` 这个点上。
 *
 * move-tool / endpoint-handles 用它决定邻墙的哪个端点要跟着走。
 * 一堵墙的两端可能同时命中（退化成一个点的墙），所以返回的是两个布尔而不是枚举。
 */
export function wallEndsAt(
  wall: WallNode,
  keys: ReadonlySet<string>,
): { start: boolean; end: boolean } {
  return {
    start: keys.has(quantizeKey(wallStart(wall), JUNCTION_TOLERANCE)),
    end: keys.has(quantizeKey(wallEnd(wall), JUNCTION_TOLERANCE)),
  }
}

// M4 只有一层，所以是一个槽位而不是 Map<levelId, …>。M8 加楼层时换成 Map。
let cache: CacheEntry | null = null

/**
 * 逐字段精确比较，**不哈希、不比引用**。
 *
 * 陈旧命中会静默渲染出错误的墙角，而 4 个数值比较 × N 堵墙是微秒级 ——
 * 比那个风险便宜得多。
 *
 * 只比影响斜接的字段。**不要把 height 加进来** —— 改层高不改平面斜接，
 * 比了会让 M8 的「改层高」触发全场重算。
 */
export function sameMiterInputs(a: readonly WallNode[], b: readonly WallNode[]): boolean {
  if (a.length !== b.length) return false

  for (let i = 0; i < a.length; i += 1) {
    const x = a[i]
    const y = b[i]
    if (x === y) continue
    if (!x || !y) return false
    if (
      x.id !== y.id ||
      x.start[0] !== y.start[0] ||
      x.start[1] !== y.start[1] ||
      x.end[0] !== y.end[0] ||
      x.end[1] !== y.end[1] ||
      x.thickness !== y.thickness
    ) {
      return false
    }
  }

  return true
}

export function getCachedLevelMiters(walls: readonly WallNode[]): MiterData {
  if (cache && sameMiterInputs(cache.walls, walls)) return cache.data

  const data = calculateLevelMiters([...walls])
  cache = { walls, data }
  return data
}

 * 缓存是模块级的，比任何一次 mount 都活得久。
 * M9 加载存档、以及测试之间，都必须调它。
 */
export function clearLevelMiterCache(): void {
  cache = null
}

import { type Point2D } from '../lib/geometry-2d'
import type { AnyNodeId } from './types'
import { wallEnd, wallStart, type WallNode } from './wall'

export const DEFAULT_GRID_STEP = 0.1
export const ENDPOINT_SNAP_RADIUS = 0.35

export type SnapOptions = {
  /** 不参与吸附的墙。拖 A 的端点时必须排除 A 自己，否则它吸住自己拖不动。 */
  ignoreIds?: ReadonlySet<AnyNodeId>
  radius?: number
  step?: number
}

export function snapToGrid(p: Point2D, step: number = DEFAULT_GRID_STEP): Point2D {
  if (!(step > 0)) return p
  return { x: Math.round(p.x / step) * step, y: Math.round(p.y / step) * step }
}

/** 半径内最近的已有端点；没有则 null。 */
export function nearestEndpoint(
  p: Point2D,
  walls: readonly WallNode[],
  options?: SnapOptions,
): Point2D | null {
  const ignoreIds = options?.ignoreIds
  const radius = options?.radius ?? ENDPOINT_SNAP_RADIUS
  const radiusSquared = radius * radius

  let best: Point2D | null = null
  let bestDistanceSquared = Number.POSITIVE_INFINITY

  for (const wall of walls) {
    if (ignoreIds?.has(wall.id)) continue

    for (const candidate of [wallStart(wall), wallEnd(wall)]) {
      const dx = candidate.x - p.x
      const dy = candidate.y - p.y
      const distanceSquared = dx * dx + dy * dy
      if (distanceSquared > radiusSquared || distanceSquared >= bestDistanceSquared) continue

      best = candidate
      bestDistanceSquared = distanceSquared
    }
  }

  return best
}

/**
 * 端点优先，退化到网格。**这个顺序是唯一的公开入口，不要在调用方自己组合。**
 *
 * 反过来（先吸网格）会这样出事：一个落在 (1.03, 2.07) 的已有端点先被吸到
 * (1.0, 2.1)，端点吸附随后发现自己已经不在半径内 —— 于是墙角差 3 厘米。
 * 肉眼看不见，但 quantizeKey 把两端分进不同的桶，**斜接静默失效**。
 */
export function snapPoint(
  p: Point2D,
  walls: readonly WallNode[],
  options?: SnapOptions,
): Point2D {
  return nearestEndpoint(p, walls, options) ?? snapToGrid(p, options?.step)
}

import type { Point2D } from '../../core/lib/geometry-2d'

const raycaster = new THREE.Raycaster()
const plane     = new THREE.Plane()
const UP        = new THREE.Vector3(0, 1, 0)
// 复用模块级 scratch 是安全的 —— 我们立刻读出 x/z 并返回一个新对象，
// 从不把 scratch 本身交给调用方。这正是可以复用的判据。

/** 屏幕 NDC 点 → 地平面上的世界点。
 *  纯数学，不依赖任何实体 mesh，所以永不被遮挡，正交 / 透视都成立。 */
export function screenToGround(
  pointer: THREE.Vector2,   // NDC，[-1,1]。R3F 的 useThree().pointer 已经是这个
  camera: THREE.Camera,
  planeY = 0,
): Point2D | null {
  raycaster.setFromCamera(pointer, camera)
  // ⚠ Plane 第二个参数是「有符号距离常数」，不是高度。

  return { x: hit.x, y: hit.z }        // ← 世界 Z 落进 Point2D.y
}

/** 客户端坐标 → NDC。写进传入的 target 并返回它。 */
export function eventToNdc(
  event: { clientX: number; clientY: number },
  element: HTMLElement,
  target: THREE.Vector2,
): THREE.Vector2 {
  const rect = element.getBoundingClientRect()
  return target.set(
    ((event.clientX - rect.left) / rect.width) * 2 - 1,
    -((event.clientY - rect.top) / rect.height) * 2 + 1,
  )
}

/** 一步到位：原生指针事件 → 地平面世界点。三个工具都用它，别再各写一遍。 */
export function eventToGround(
  event: { clientX: number; clientY: number },
  element: HTMLElement,
  camera: THREE.Camera,
  planeY = 0,
): Point2D | null {
  return screenToGround(eventToNdc(event, element, ndc), camera, planeY)
}

import { useScene } from "../../../core/store/use-scene";
import { useViewer } from "../../../viewer/store/use-viewer";

export type DragSession = {
    /** 结束这次拖拽。幂等 —— 重复调用什么都不做。 */
    end: (mode: 'commit' | 'cancel') => void
}

type DragSessionHandlers = {
    onMove: (event: PointerEvent) => void
    onCommit: () => void
    onCancel: () => void
}

/**
 * 一次指针拖拽的骨架：租约、全局监听、四种收尾路径。
 *
 * 两个工具共用它，是为了让「租约泄漏」在结构上不可能发生 ——
 * 泄漏一次，历史就永久暂停，之后所有编辑都撤不回来，
 * 而症状（Ctrl+Z 没反应）离病因（某个 return 分支忘了 release）非常远。
 *
 * 监听器挂 window 而不是 canvas：拖到画布外再松手时 canvas 收不到
 * pointerup，你会得到一堵永远粘着光标的墙。
 */
export function startDragSession({ onMove, onCommit, onCancel }: DragSessionHandlers): DragSession {
    useViewer.getState().setInputDragging(true)
    const releaseHistory = acquireSceneHistoryPause(useScene)

    let finished = false

    const finish = (mode: 'commit' | 'cancel') => {
        if (finished) return
        finished = true

        window.removeEventListener('pointermove', handleMove)
        window.removeEventListener('pointerup', handleUp)
        window.removeEventListener('pointercancel', handleCancel)
        window.removeEventListener('keydown', handleKey)
        window.removeEventListener('blur', handleBlur)

        // ⚠ 顺序：先 resume，再让 onCommit 写 store。
        //   反过来的话，暂停期间的写入根本不产生 pastState，
        //   那条改动永远撤不回来。
        releaseHistory()
        useViewer.getState().setInputDragging(false)

        if (mode === 'commit') onCommit()
        else onCancel()
    }

    const handleMove = (event: PointerEvent) => onMove(event)
    const handleUp = (event: PointerEvent) => { if (event.button === 0) finish('commit') }
    const handleCancel = () => finish('cancel')
    const handleKey = (event: KeyboardEvent) => { if (event.key === 'Escape') finish('cancel') }
    const handleBlur = () => finish('cancel')

    window.addEventListener('pointermove', handleMove)
    window.addEventListener('pointerup', handleUp)
    window.addEventListener('pointercancel', handleCancel)
    window.addEventListener('keydown', handleKey)
    window.addEventListener('blur', handleBlur)

    return { end: finish }
}

import { quantizeKey, type Point2D } from "../../../core/lib/geometry-2d";
import type { AnyNodeId } from "../../../core/schema/types";
import { wallEnd, wallStart, type WallNode } from "../../../core/schema/wall";
import type { NodeOverride } from "../../../core/store/use-live-overrides";
import { useScene } from "../../../core/store/use-scene";
import { JUNCTION_TOLERANCE } from "../../../core/systems/wall/wall-mitering";

export type OverrideEntry = readonly [AnyNodeId, NodeOverride]

/** 一个端点从哪儿搬到哪儿。整墙拖是两条，端点拖是一条。 */
export type PointMove = { from: Point2D; to: Point2D }

/** 当前文档里的墙（不含 live 覆盖 —— 拖拽期间要的正是没被覆盖的原始值）。 */
export function documentWalls(): WallNode[] {
    return Object.values(useScene.getState().nodes).filter(
        (n): n is WallNode => n.type === 'wall',
    )
}

/**
 * 邻墙跟随：任何贴在 `moves[i].from` 上的端点，改到对应的 `to`。
 *
 * 只覆盖被拖的那堵墙的话，calculateLevelMiters 看到的是「主墙已移动、
 * 邻墙还在原处」—— 共端点断开，斜接消失，墙角在拖动全程闪烁，松手才复原。
 */
export function linkedWallOverrides(
    walls: readonly WallNode[],
    moves: readonly PointMove[],
    excludeIds: ReadonlySet<AnyNodeId>,
): OverrideEntry[] {
    const targetByKey = new Map<string, Point2D>()
    for (const move of moves) {
        targetByKey.set(quantizeKey(move.from, JUNCTION_TOLERANCE), move.to)
    }

    const entries: OverrideEntry[] = []

    for (const wall of walls) {
        if (excludeIds.has(wall.id)) continue

        const nextStart = targetByKey.get(quantizeKey(wallStart(wall), JUNCTION_TOLERANCE))
        const nextEnd = targetByKey.get(quantizeKey(wallEnd(wall), JUNCTION_TOLERANCE))
        if (!nextStart && !nextEnd) continue

        const patch: NodeOverride = {}
        if (nextStart) patch.start = [nextStart.x, nextStart.y]
        if (nextEnd) patch.end = [nextEnd.x, nextEnd.y]
        entries.push([wall.id, patch])
    }

    return entries
}

  anchor: Point2D
  center: Point2D
  walls: WallNode[]

export function MoveTool(): null {
  const activeTool = useEditor((s) => s.activeTool)
  const { gl, camera } = useThree()

  const candidateRef = useRef<Candidate | null>(null)
  const sessionRef = useRef<DragSession | null>(null)
  const entriesRef = useRef<OverrideEntry[]>([])

  useEffect(() => {
    if (activeTool !== 'select') return
    const el = gl.domElement

    // ── 提交 / 取消 ──────────────────────────────────────────
    const commit = () => {
      const entries = entriesRef.current
      // 历史已经在 drag-session 里 resume 过了，这里写的才进得了 undo。
      runAsSingleSceneHistoryStep(useScene, () => {
        const { updateNode } = useScene.getState()
        for (const [id, patch] of entries) updateNode(id, patch)
      })
      teardown()
    }

    const cancel = () => {
      // 拖拽全程没写过主 store，清掉覆盖就等于回到原位。
      teardown()
    }

    const teardown = () => {
      entriesRef.current = []
      candidateRef.current = null
      sessionRef.current = null
      useLiveOverrides.getState().clearAll()
      useInteractionScope.getState().end()
    }

    // ── 拖拽中 ───────────────────────────────────────────────
    const onDragMove = (event: PointerEvent) => {
      const candidate = candidateRef.current
      if (!candidate) return

      const cursor = eventToGround(event, el, camera)
      if (!cursor) return

      const rawDelta = {
        x: cursor.x - candidate.anchor.x,
        y: cursor.y - candidate.anchor.y,

      // 整墙拖只吸网格（端点吸附留给手柄）。吸的是**墙心的绝对坐标**，

        x: candidate.center.x + rawDelta.x,
        y: candidate.center.y + rawDelta.y,
      })
      const delta = { x: target.x - candidate.center.x, y: target.y - candidate.center.y }

      const originalStart = wallStart(candidate.wall)
      const originalEnd = wallEnd(candidate.wall)
      const nextStart = { x: originalStart.x + delta.x, y: originalStart.y + delta.y }
      const nextEnd = { x: originalEnd.x + delta.x, y: originalEnd.y + delta.y }

      const self: OverrideEntry = [
        candidate.wall.id,
        { start: [nextStart.x, nextStart.y], end: [nextEnd.x, nextEnd.y] },
      ]
      const linked = linkedWallOverrides(
        candidate.walls,
        [
          { from: originalStart, to: nextStart },
          { from: originalEnd, to: nextEnd },
        ],
        new Set([candidate.wall.id]),
      )

      entriesRef.current = [self, ...linked]
      // 一次 setMany，不是 N 次 set —— 见 use-live-overrides.ts 的注释。
      useLiveOverrides.getState().setMany(entriesRef.current)

    //
    // 在 pointerdown 就 begin('moving') 会让 selectionEnabled 立刻变假，
    // 于是「点一堵墙选中它」永远不再发生。所以等指针真的超过 4px 阈值
    // 才把候选升格成拖拽 —— 这正好复用 M3 的 isClickGesture。
    const promote = (event: PointerEvent) => {
      const candidate = candidateRef.current
      if (!candidate) return

      window.removeEventListener('pointermove', onCandidateMove)
      window.removeEventListener('pointerup', onCandidateUp)

      useInteractionScope.getState().begin({
        kind: 'moving',
        nodeId: candidate.wall.id,
        origin: candidate.anchor,
      })
      sessionRef.current = startDragSession({ onMove: onDragMove, onCommit: commit, onCancel: cancel })
      onDragMove(event)
    }

    const onCandidateMove = (event: PointerEvent) => {
      if (isClickGesture(event)) return   // 还在阈值内，仍可能是一次点击
      promote(event)
    }

    const onCandidateUp = () => {
      window.removeEventListener('pointermove', onCandidateMove)
      window.removeEventListener('pointerup', onCandidateUp)
      candidateRef.current = null
      useViewer.getState().setInputDragging(false)
    }

    const onWallPointerDown = (e: NodeEvent) => {
      if (getScope().kind !== 'idle') return
      const wall = e.node
      if (wall.type !== 'wall') return

      const anchor = eventToGround(e.nativeEvent, el, camera)
      if (!anchor) return

      candidateRef.current = {
        wall,
        anchor,
        center: midpoint(wallStart(wall), wallEnd(wall)),
        walls: documentWalls(),
      }

      // 立刻掐掉相机 —— 等阈值到了再关，前 4px 已经把视角转走了。
      // 纯点击时 onCandidateUp 会把它放回来，用户看不出差别。
      useViewer.getState().setInputDragging(true)

      window.addEventListener('pointermove', onCandidateMove)
      window.addEventListener('pointerup', onCandidateUp)
    }

    emitter.on('wall:pointerdown', onWallPointerDown)

    return () => {
      emitter.off('wall:pointerdown', onWallPointerDown)
      window.removeEventListener('pointermove', onCandidateMove)
      window.removeEventListener('pointerup', onCandidateUp)
      // 卸载时必须收尾，否则租约泄漏 ⟹ 历史永久暂停。
      sessionRef.current?.end('cancel')
      candidateRef.current = null
      useViewer.getState().setInputDragging(false)
    }
  }, [activeTool, gl, camera])

  return null
}

function WallDraftPreview({ cursorRef }: { cursorRef: React.RefObject<Point2D | null> }) {
  const lineRef = useRef<ComponentRef<typeof Line>>(null)

  useFrame(() => {
    const line = lineRef.current
    if (!line) return

    const cursor = cursorRef.current

      return

function dragWallBy(id: AnyNodeId, dx: number, dy: number, frames = 60): void {
  const original = wall(id)
  const release = acquireSceneHistoryPause(useScene)

  let last = { start: original.start, end: original.end }
  for (let f = 1; f <= frames; f += 1) {
    const t = f / frames
    last = {
      start: [original.start[0] + dx * t, original.start[1] + dy * t],
      end: [original.end[0] + dx * t, original.end[1] + dy * t],
    }
    useLiveOverrides.getState().setMany([[id, last]])
  }

  // 顺序：先 resume，再写。
  release()
  runAsSingleSceneHistoryStep(useScene, () => {
    useScene.getState().updateNode(id, last)
  })
  useLiveOverrides.getState().clearAll()
}

核心是 countNotifications() 那个辅助函数 —— 数一次操作让订阅者被唤醒几次。

「setMany 写 N 个节点只唤醒一次」+「逐个 set 唤醒 N 次」这一对，就是 §02 A 那句「setMany 不是可选优化」的可执行版本。逐个 set 会让 useLevelMiters 在一帧内重算 N 次斜接，而中间那几次算的是「主墙已移动、邻墙还没动」的自相矛盾状态。

最后一条锁住 useEffectiveNode 的前提：未被改动的条目必须保持同一个引用，否则那个 useMemo 每次都失效。

import { beforeEach, describe, expect, it } from 'vitest'
import type { AnyNodeId } from '../schema/types'
import { WallNode } from '../schema/wall'
import { getEffectiveNode, useLiveOverrides } from './use-live-overrides'

const wall = (id: string, start: [number, number], end: [number, number]) =>
  WallNode.parse({ id: `wall_${id}`, type: 'wall', start, end })

const A = wall('a', [0, 0], [4, 0])
const B = wall('b', [4, 0], [4, 3])

/** 数一次操作让订阅者被唤醒几次。 */
function countNotifications(run: () => void): number {
  let n = 0
  const unsubscribe = useLiveOverrides.subscribe(() => {
    n += 1
  })
  run()
  unsubscribe()
  return n
}

beforeEach(() => useLiveOverrides.getState().clearAll())

describe('getEffectiveNode', () => {
  it('没有覆盖时原样返回入参（同一个引用）', () => {
    expect(getEffectiveNode(A)).toBe(A)
  })

  it('有覆盖时合并，且不改动原对象', () => {
    useLiveOverrides.getState().set(A.id, { start: [1, 1] })

    const effective = getEffectiveNode(A)
    expect(effective.start).toEqual([1, 1])
    expect(effective.end).toEqual([4, 0]) // 未覆盖的字段保留
    expect(A.start).toEqual([0, 0]) // 文档没被动过
  })

  it('同一个 id 二次 set 是合并不是替换', () => {
    useLiveOverrides.getState().set(A.id, { start: [1, 1] })
    useLiveOverrides.getState().set(A.id, { end: [5, 1] })

    const effective = getEffectiveNode(A)
    expect(effective.start).toEqual([1, 1])
    expect(effective.end).toEqual([5, 1])
  })

  it('clear 之后回到文档值', () => {
    useLiveOverrides.getState().set(A.id, { start: [1, 1] })
    useLiveOverrides.getState().clear(A.id)
    expect(getEffectiveNode(A)).toBe(A)
  })
})

describe('通知次数', () => {
  it('setMany 写 N 个节点只唤醒订阅者一次', () => {
    const n = countNotifications(() => {
      useLiveOverrides.getState().setMany([
        [A.id, { start: [1, 1] }],
        [B.id, { start: [1, 1] }],
      ])
    })

    // 这一条就是「setMany 不是可选优化」的可执行版本：
    // 逐个 set 会让 useLevelMiters 在一帧内重算 N 次斜接，
    // 而中间那几次算的是「主墙已移动、邻墙还没动」的自相矛盾状态。
    expect(n).toBe(1)
  })

  it('逐个 set 会唤醒 N 次 —— 对照组', () => {
    const n = countNotifications(() => {
      useLiveOverrides.getState().set(A.id, { start: [1, 1] })
      useLiveOverrides.getState().set(B.id, { start: [1, 1] })
    })
    expect(n).toBe(2)
  })

  it('setMany 传空数组不唤醒', () => {
    expect(countNotifications(() => useLiveOverrides.getState().setMany([]))).toBe(0)
  })

  it('已经空了再 clearAll 不唤醒', () => {
    expect(countNotifications(() => useLiveOverrides.getState().clearAll())).toBe(0)
  })

  it('clear 一个不存在的 id 不唤醒', () => {
    expect(
      countNotifications(() => useLiveOverrides.getState().clear('wall_nope' as AnyNodeId)),
    ).toBe(0)
  })
})

describe('Map 引用', () => {
  it('每次写都换 Map 引用 —— 原地 set 的话订阅者收不到通知', () => {
    const before = useLiveOverrides.getState().overrides
    useLiveOverrides.getState().set(A.id, { start: [1, 1] })
    expect(useLiveOverrides.getState().overrides).not.toBe(before)
  })

  it('同一条目未被改动时保持引用不变 —— useEffectiveNode 的 useMemo 靠它', () => {
    useLiveOverrides.getState().set(A.id, { start: [1, 1] })
    const entryA = useLiveOverrides.getState().overrides.get(A.id)

    useLiveOverrides.getState().set(B.id, { start: [2, 2] })

    expect(useLiveOverrides.getState().overrides.get(A.id)).toBe(entryA)
  })
})

项目里没装 jsdom —— 手搓一个 12 行的 window 就够了

startDragSession 只用到 window 的 addEventListener / removeEventListener。一个 Map<string, Set<fn>> 加三个方法，用 Reflect.set(globalThis, 'window', fake) 装上去。不装 jsdom（+80MB 依赖、拖慢每次 pnpm test），也不改任何生产代码。

判据：需要的是 DOM 的接口还是 DOM 的行为。只用 addEventListener 的话是前者，替身就够；要布局、要冒泡、要 getBoundingClientRect 的话是后者，那才必须上 jsdom。

测的是四条收尾路径（pointerup / Esc / pointercancel / blur）和租约不泄漏。租约泄漏一次，历史就永久暂停，之后所有编辑都撤不回来，而症状（Ctrl+Z 没反应）离病因（某个分支忘了 release）非常远 —— 正是最该上测试的地方。

onCommit 里把 getSceneHistoryPauseDepth() 打进日志，于是断言 commit(depth=0) 就等于断言「resume 在 write 之前跑完了」。

 * addEventListener / removeEventListener —— 手搓一个 12 行的替身就够了。
 *
 * 这一份测的是**四条收尾路径**和**租约不泄漏**。租约泄漏一次，
 * 历史就永久暂停，之后所有编辑都撤不回来，而症状（Ctrl+Z 没反应）

type Listener = (event: unknown) => void

function installFakeWindow() {
  const listeners = new Map<string, Set<Listener>>()

  const fake = {
    addEventListener(type: string, fn: Listener) {
      let set = listeners.get(type)
      if (!set) {
        set = new Set()
        listeners.set(type, set)
      }
      set.add(fn)
    },
    removeEventListener(type: string, fn: Listener) {
      listeners.get(type)?.delete(fn)
    },
    dispatch(type: string, event: unknown = {}) {
      for (const fn of [...(listeners.get(type) ?? [])]) fn(event)
    },
    total() {
      let n = 0
      for (const set of listeners.values()) n += set.size
      return n
    },
  }

  Reflect.set(globalThis, 'window', fake)
  return fake
}
