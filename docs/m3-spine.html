M3 一次点击只干一件事

两个工具（选择、画墙）共存，指针输入永远只有一个归属。 画墙画到一半点在已有墙上——落点，不选中。松开相机拖拽——什么都不发生。 再加上链式画墙：画完一堵，终点自动接下一堵。

这是全项目认知密度最高的一个里程碑。代码量不到 M2 的一半， 但它决定了后面 11 个里程碑里每一个新工具的接入方式。

②

找「之前是怎么错的」

规格书里最值钱的段落，是描述它取代了什么的那一段。 M3 的那段在 interaction-scope.md 开头：

"...was re-derived from 7+ independent flags (movingNode, placementDragMode, activeHandleDrag, curvingWall, editingHole, movingWallEndpoint…). Every overlay and pick site re-derived its behaviour from a different subset, so the flags could drift into illegal combinations."

那七个标志的名字本身就是一张地图——它告诉你这个 scope 最终要吞掉哪些交互。movingNode → M4，editingHole → M7， curvingWall → 我们不做。

可迁移的判据：

问题答不上来意味着
这个设计排除了哪些非法状态？你不知道它解决什么，抄了也是背诵
不用它会怎么错？无法判断自己需不需要它
它是设计出来的还是重构出来的？重构出来的通常不能省，设计出来的常常可以

一个设计的价值 = 它排除掉的错误状态。M3 的 spine 是重构的产物 （文档明说了 "Before this..."），所以它不能省——只能精简。

④

抽不变量

每个机制都能压成 1–3 句永远为真的话。 interaction-scope.md 末尾正好有一节叫 ## Rules， 规格书自己抽好了： 

① One owner, one scope.
   只有 useInteractionScope 写 scope，且只经 begin/update/end/endIf。

② end is atomic and payload-free.
   永远不许在 idle 上留下 nodeId / 半清的标志。

③ update cannot change kind.
   换交互是 begin，不是打补丁。

④ selectionEnabled(scope) === (kind === 'idle')
   任何活跃交互进行中，指针属于那个交互的躯体。

这四句直接翻译成了 §07 第 18 项的 8 个测试用例，一一对应：

不变量测试用例
④idle 允许选择 / 任何活跃交互都掐断选择
③update 不能改变 kind / update 在 idle 时被忽略
②end 是原子的：没有载荷能活过它
①endIf 不掐掉不匹配的 scope

这一步是整个七步里最可迁移的。不变量同时是三样东西： 测试用例、code review 的标准、 三个月后你判断某处改动合不合法的依据。 写不出不变量，说明你还没真的理解这个机制——不是没记住，是没理解。

01这个 bug 现在就在你的代码里

一次点击，两个监听器，各干各的

你现在的代码有两条互不知情的指针输入路径：

// src/app/tools/wall-tool.tsx:56
el.addEventListener('pointerdown', onPointerDown)   ← canvas DOM 级，点哪都触发

// src/viewer/components/wall-renderer.tsx:36
onClick={(e) => { e.stopPropagation(); console.log('[pick]', node.id) }}
                                       ↑ R3F 射线级，点中墙才触发

在墙工具激活时点一堵已有的墙，两个都会触发： 落一个点，同时打印一次 [pick]。 现在无害，因为 [pick] 只是 console.log。 M3 第一件事就是把它换成真的选中——那一刻 bug 就现形了。

还有三个同源的：

  • 相机拖拽的松手会选中东西。OrbitControls 转视角，松手时 R3F 合成一次 click，落在光标下的任何 mesh 上。
  • 画墙到一半切工具，起点去哪了？pendingRef 在 useEffect 清理里被清——但清理时机取决于依赖数组，不取决于你的意图。
  • Esc 该取消什么？取消画墙的起点，还是取消选中？两个监听器都想响应。

这四个问题看起来是四个 bug。它们是同一个 bug： 没有任何一处代码知道"用户此刻在干什么"。每个监听器都在用自己那点局部信息猜。

原项目的原话

wiki/architecture/interaction-scope.md 开头记的就是这段历史—— 他们猜了很久才收手：

"Before this, 'what is the user doing right now?' was re-derived from 7+ independent flags (movingNode, placementDragMode, activeHandleDrag, curvingWall, editingHole, movingWallEndpoint…). Every overlay and pick site re-derived its behaviour from a different subset, so the flags could drift into illegal combinations (moving + curving at once; a stale movingNode after a drag ended)."

修法是一个判别联合，叫 the spine，配一条铁律： 

selectionEnabled(scope) === (scope.kind === 'idle')

// 任何交互进行中，指针属于那个交互的躯体，
// 拾取选择必须被掐断 —— 不是"尽量避让"，是掐断。
M3 最重要的一个设计决定

工具一旦被选中就持有 scope，不是等到指针按下才持有。 按 W 切到墙工具的那一刻就 begin({ kind: 'drafting', tool: 'wall', points: [] })， 切回选择工具才 end()。

为什么不是"按下时进入、松开时退出"？因为那样第一次点击时 scope 还是 idle，selectionEnabled 返回 true， 你的第一个落点会同时选中那堵墙——bug 原封不动。

原项目在 sculpting 变体上写了同样的道理： "A brush that only claimed the scope between pointer-down and -up would flicker all of that back on between dabs."

02事件的两次转身

viewer 发生了什么，app 决定它意味着什么

M3 引入事件总线（mitt）。不是为了解耦而解耦——它是 "viewer 不许知道选中"这条边界唯一能落地的形式。 

mesh 上的 R3F 指针事件
   │
   │  第一次转身：R3F 事件 → 领域事件（viewer 做）
   ▼
useNodeEvents(node, 'wall')  →  emitter.emit('wall:click', { node, point, … })
   │
   │  viewer 的职责到此为止。它不知道 click 意味着什么。
   ▼
   │  第二次转身：领域事件 → 编辑语义（app 做）
   ▼
SelectionManager 监听 'wall:click'
   ├─ selectionEnabled(scope) 为假 → 直接丢弃
   └─ 为真 → useEditor.select(node.id)

中间那道横线就是 viewer-isolation。换掉 app 层，viewer 一行不用改—— 一个只读展示页可以监听同样的 wall:click 去弹出信息卡片， 而不是选中。

为什么不用回调 props（<Viewer onNodeClick={…}>）？M3 只有一种事件时 确实更简单。但到 M7 你会有 click / enter / leave / move / pointerdown / pointerup / double-click 七种 × 若干节点类型，而且要穿过 SceneRenderer → NodeRenderer → WallRenderer 三层。 总线的价值不在解耦，在于不用逐层穿线。

事件键的格式是 <nodeType>:<suffix>——wall:click、 door:enter。另外一族是 grid:*，表示"点在空地上"， 由一个手动射线的 hook 发出，不来自任何 mesh。 M3 用它来做"点空白处取消选中"。

"test":   "vitest run",

这些测试已经跑过了，结果是红的。根因是一个字符： 

// core/lib/geometry-2d.ts —— pointOnSegment
const L2 = ab.x + ab.y * ab.y      // ❌ 第一项少了一个平方
//         ^^^^ 应该是 ab.x * ab.x

对 (0,0)→(4,0)，正确的 L2 是 16，实际算出 4。投影参数 t 被放大 4 倍， 中点 (2,0) 算出 t = 2，被判成「在延长线上」⟹ pointOnSegment 永远返回 false ⟹ T 型接头永远检测不到 ⟹ 撞上来的墙不切齐。三个失败用例同一个根因。 它在 3D 画面上的表现只是「T 型墙角有条缝」，你会先去怀疑挤出、绕向、法线。

M3 结束时这些必须还在

最后一条值得留意。useNodeEvents 会发出 enter / leave / move，但 M3 一个监听者都没有。 这不是死代码——它们是同一个翻译层的自然产物， 少发反而要加分支。M12 加悬停高亮时零改动接上。

 * 与任何监听器的注册顺序无关。

const CLICK_SLOP_PX = 4

let downX = 0
let downY = 0
let armed = false

export function beginGesture(e: { clientX: number; clientY: number }): void {
  downX = e.clientX
  downY = e.clientY
  armed = true
}

/** 松手位置离按下位置不超过 4px 才算点击。转视角、拖拽都会超过。 */
export function isClickGesture(e: { clientX: number; clientY: number }): boolean {
  if (!armed) return false
  const dx = e.clientX - downX
  const dy = e.clientY - downY
  return dx * dx + dy * dy <= CLICK_SLOP_PX * CLICK_SLOP_PX
}

import { sceneRegistry } from '../../core/registry/scene-registry'
import { isClickGesture } from '../lib/pointer-gesture'
import { screenToGround } from '../lib/pointer-plane'

const ndc = new THREE.Vector2()
const raycaster = new THREE.Raycaster()

/**
 * 发出 grid:click：点击且没有命中任何已注册节点。
 *
 * 为什么要自己再射一次线，而不是靠「谁先谁后」：
 * DOM 级监听器不知道 R3F 命中了什么。如果 grid 无条件发，点一堵墙就会
 * 同时触发「选中」和「取消选中」，谁赢取决于两个监听器的注册顺序。
 * 对 sceneRegistry 直接射一次线是确定性的答案，与顺序无关。
 *
 * 代价是一次多余的射线。几十堵墙无所谓。
 */
export function useGridEvents(planeY = 0): void {
  const { gl, camera } = useThree()

  useEffect(() => {
    const el = gl.domElement

    const onPointerUp = (e: PointerEvent) => {
      if (e.button !== 0) return
      if (!isClickGesture(e)) return          // 拖拽，不是点击

      const r = el.getBoundingClientRect()
      ndc.set(
        ((e.clientX - r.left) / r.width) * 2 - 1,
        -((e.clientY - r.top) / r.height) * 2 + 1,
      )

      // 命中了任何节点 → 这一击属于那个节点，grid 不发声
      raycaster.setFromCamera(ndc, camera)
      const targets = Array.from(sceneRegistry.nodes.values())
      if (targets.length > 0 && raycaster.intersectObjects(targets, true).length > 0) return

      const p = screenToGround(ndc, camera, planeY)
      if (!p) return
      emitter.emit('grid:click', { point: [p.x, planeY, p.y], nativeEvent: e })
    }

    el.addEventListener('pointerup', onPointerUp)
    return () => el.removeEventListener('pointerup', onPointerUp)
  }, [gl, camera, planeY])
}

import { emitter } from '../../core/events/bus'
import type { NodeEvent, NodeEventKey, NodeEventSuffix } from '../../core/events/types'
import type { AnyNode, AnyNodeType } from '../../core/schema/types'
import { isClickGesture } from '../lib/pointer-gesture'
import { useViewer } from '../store/use-viewer'

/**
 * 从判别联合里取出某个 kind 的节点形状。
 * 加新 kind 时这里自动跟上，不需要手维护 kind → 节点类型 的映射表。
 */
type NodeByKind<K extends AnyNodeType> = Extract<AnyNode, { type: K }>

/**
 * 第一次转身：R3F 指针事件 → 领域事件。
 * viewer 的职责到 emit 为止 —— 它不知道 click 意味着什么。
 *
 * 用法：<mesh {...useNodeEvents(node, 'wall')} />
 */
export function useNodeEvents<K extends AnyNodeType>(node: NodeByKind<K>, type: K) {
  const emit = (suffix: NodeEventSuffix, e: ThreeEvent<PointerEvent>) => {
    const payload: NodeEvent<NodeByKind<K>> = {
      node,
      point: [e.point.x, e.point.y, e.point.z],
      object: e.object,
      stopPropagation: () => e.stopPropagation(),
    }
    // mitt 的 emit 按固定键联合定型；这里的键是它的子集，
    // 用 as 把 kind 具体的载荷送过泛型表面。
    emitter.emit(`${type}:${suffix}` as NodeEventKey, payload as NodeEvent)
  }

  // 相机拖拽时抑制悬停类事件，避免转视角时高亮乱闪。
  // 点击类不靠它 —— 靠 isClickGesture，那个与监听器顺序无关。
  const hoverSuppressed = () => useViewer.getState().cameraDragging

  return {
    onPointerDown: (e: ThreeEvent<PointerEvent>) => {
      if (e.button !== 0) return
      emit('pointerdown', e)
    },
    onPointerUp: (e: ThreeEvent<PointerEvent>) => {
      if (e.button !== 0) return
      emit('pointerup', e)
      // 在 pointerup 里合成 click，比 R3F 自带的 onClick 宽容 ——
      // 后者在指针移动 1px 时就不触发，用户会觉得「点了没反应」。
      if (isClickGesture(e.nativeEvent)) emit('click', e)
    },
    // 显式吃掉 R3F 自带的 click，否则和上面合成的那次双触发。
    onClick: (_e: ThreeEvent<MouseEvent>) => {},
    onPointerEnter: (e: ThreeEvent<PointerEvent>) => {
      if (!hoverSuppressed()) emit('enter', e)
    },
    onPointerLeave: (e: ThreeEvent<PointerEvent>) => {
      if (!hoverSuppressed()) emit('leave', e)
    },
    onPointerMove: (e: ThreeEvent<PointerEvent>) => {
      if (!hoverSuppressed()) emit('move', e)
    },
  }
}

import type { Point2D } from '../../../core/lib/geometry-2d'

/**
 * 「用户此刻在干什么」的唯一权威描述。
 *
 * 在这之前，这个问题由若干个互不知情的布尔标志各自回答：wall-tool 的
 * pendingRef、wall-renderer 的 onClick、OrbitControls 的 enableRotate。
 * 每一处都用自己那点局部信息猜，于是它们会漂移到非法组合里。
 *
 * 收成一个判别联合之后，这些组合在类型上就不可表达：
 * 任一时刻恰好一个交互，idle 不携带任何载荷。
 */
export type InteractionScope =
  | { kind: 'idle' }
  // 逐点绘制折线（M6 的楼板轮廓复用同一个变体）。
  // points 是已确定的顶点，不含跟随光标的那一个。
  | { kind: 'drafting'; tool: 'wall'; points: Point2D[] }

export type InteractionKind = InteractionScope['kind']
export type ActiveInteractionScope = Exclude<InteractionScope, { kind: 'idle' }>

export const IDLE_SCOPE: InteractionScope = { kind: 'idle' }

/** 共享的空数组：每次返回新数组会让下游的 memo / 相等性判断永远失效。 */
const NO_POINTS: readonly Point2D[] = Object.freeze([])

export function isIdle(s: InteractionScope): s is { kind: 'idle' } {
  return s.kind === 'idle'
}

export function isActive(s: InteractionScope): s is ActiveInteractionScope {
  return s.kind !== 'idle'
}

/**
 * 唯一的拾取闸门。
 *
 * 一行，看着可笑地简单 —— 但所有「这次点击该不该选中」的判断都必须经过它，
 * 不许在别处重新推导。重新推导正是 7 个布尔标志时代的形状。
 */
export function selectionEnabled(s: InteractionScope): boolean {
  return s.kind === 'idle'
}

/** 当前草稿的已确定顶点。非 drafting 返回共享空数组。 */
export function draftPoints(s: InteractionScope): readonly Point2D[] {
  return s.kind === 'drafting' ? s.points : NO_POINTS
}

/** 草稿的最后一个顶点 —— 链式画墙的起点。 */
export function lastDraftPoint(s: InteractionScope): Point2D | null {
  const pts = draftPoints(s)
  return pts.length > 0 ? pts[pts.length - 1]! : null

import { create } from 'zustand'
import {
  type ActiveInteractionScope,
  IDLE_SCOPE,
  type InteractionScope,
  selectionEnabled,
} from '../lib/interaction/scope'

/**
 * 交互状态机的单一所有者。
 *
 * 唯一可写的形状就是 InteractionScope 本身 —— 不提供任何 setXxx 单字段
 * setter。没有 setter 能留下半个状态，这是全部意义所在。
 */
type InteractionScopeState = {
  scope: InteractionScope
  /** 进入一个交互。已有的活跃 scope 被原子替换（单一所有者，无生产者竞态）。 */
  begin: (scope: ActiveInteractionScope) => void
  /** 修补当前 scope 的载荷。idle 时忽略；kind 不同时忽略。 */
  update: (patch: Partial<ActiveInteractionScope>) => void
  /** 原子回到 idle。提交和取消都走它，写回还是回滚的区别在交互躯体里解决。 */
  end: () => void
  /** 只在当前 scope 满足 match 时结束 —— 别掐掉不属于你的交互。 */
  endIf: (match: (s: ActiveInteractionScope) => boolean) => void
}

export const useInteractionScope = create<InteractionScopeState>((set, get) => ({
  scope: IDLE_SCOPE,

  begin: (scope) => set({ scope }),

  update: (patch) =>
    set((state) => {
      if (state.scope.kind === 'idle') return state
      // 载荷更新不许改变正在运行的是哪个交互 —— 换交互要用 begin。
      if ('kind' in patch && patch.kind !== state.scope.kind) return state
      return { scope: { ...state.scope, ...patch } as InteractionScope }
    }),

  end: () => {
    if (get().scope.kind === 'idle') return
    set({ scope: IDLE_SCOPE })
  },

  endIf: (match) => {
    const scope = get().scope
    if (scope.kind === 'idle') return
    if (match(scope)) set({ scope: IDLE_SCOPE })
  },
}))

// —— 命令式读取，给事件处理器和 effect 用 ——
// 监听器注册一次就不该因为 scope 变化重挂，所以读快照而不是订阅。

export const getScope = (): InteractionScope => useInteractionScope.getState().scope

export const isSelectionEnabled = (): boolean => selectionEnabled(getScope())

import { Line } from '@react-three/drei'
import { useThree } from '@react-three/fiber'
import { useEffect, useState } from 'react'
import * as THREE from 'three'
import type { Point2D } from '../../core/lib/geometry-2d'
import { useScene } from '../../core/store/use-scene'
import { isClickGesture } from '../../viewer/lib/pointer-gesture'
import { screenToGround } from '../../viewer/lib/pointer-plane'
import { draftPoints, lastDraftPoint } from '../lib/interaction/scope'
import { useEditor } from '../store/use-editor'
import { getScope, useInteractionScope } from '../store/use-interaction-scope'

const ndc = new THREE.Vector2()

/**
 * 画墙工具。链式：画完一堵，终点自动成为下一堵的起点。
 *
 * 工具一被选中就持有 scope，不是等指针按下才持有。
 * 否则第一次落点时 scope 还是 idle，selectionEnabled 为真，
 * 那一下会同时选中光标下的墙 —— 也就是原来的 bug 原封不动。
 *
 * 指针输入直接走 DOM 监听器，不走事件总线：drafting 期间指针本来就属于
 * 这个交互的躯体。总线是给 idle 路径（选择 / 悬停）用的。
 */
export function WallTool() {
  const activeTool = useEditor((s) => s.activeTool)
  const { gl, camera } = useThree()
  // 跟随光标的橡皮筋端点。M3 用 state，每次移动都重渲染 —— M4 换命令式路径。
  const [cursor, setCursor] = useState<Point2D | null>(null)

  // —— 武装即持有 scope ——
  useEffect(() => {
    if (activeTool !== 'wall') return
    useInteractionScope.getState().begin({ kind: 'drafting', tool: 'wall', points: [] })
    return () => {
      // endIf 而不是 end：切走时若 scope 已被别人换掉，别乱掐。
      useInteractionScope.getState().endIf((s) => s.kind === 'drafting')
      setCursor(null)
    }
  }, [activeTool])

  // —— 指针输入 ——
  useEffect(() => {
    if (activeTool !== 'wall') return
    const el = gl.domElement

    const toGround = (e: PointerEvent): Point2D | null => {
      const r = el.getBoundingClientRect()
      ndc.set(
        ((e.clientX - r.left) / r.width) * 2 - 1,
        -((e.clientY - r.top) / r.height) * 2 + 1,
      )
      return screenToGround(ndc, camera)
    }

    const onPointerUp = (e: PointerEvent) => {
      if (e.button !== 0) return
      if (!isClickGesture(e)) return          // 拖了相机，不是落点

      const p = toGround(e)
      if (!p) return

      const scope = getScope()
      if (scope.kind !== 'drafting') return

      const last = lastDraftPoint(scope)
      if (last) {
        useScene.getState().addNode({
          type: 'wall',
          start: [last.x, last.y],
          end: [p.x, p.y],
        })
      }
      // 链式：无论是第一个点还是刚落成一堵墙，终点都成为下一段的起点。
      useInteractionScope.getState().update({ points: [p] })
    }

    const onPointerMove = (e: PointerEvent) => setCursor(toGround(e))

    const onKeyDown = (e: KeyboardEvent) => {
      // Esc 断开链条，但留在画墙工具里。
      // 「这条线画完了」和「我不想画墙了」是两件事，后者按 V。
      if (e.key === 'Escape') {
        useInteractionScope.getState().update({ points: [] })
        setCursor(null)
      }
    }

    const onContextMenu = (e: MouseEvent) => {
      e.preventDefault()
      // 右键还兼着平移相机。只有「点」才断链，「拖」是在平移。
      if (!isClickGesture(e)) return
      useInteractionScope.getState().update({ points: [] })
    }

    el.addEventListener('pointerup', onPointerUp)
    el.addEventListener('pointermove', onPointerMove)
    el.addEventListener('contextmenu', onContextMenu)
    window.addEventListener('keydown', onKeyDown)
    return () => {
      el.removeEventListener('pointerup', onPointerUp)
      el.removeEventListener('pointermove', onPointerMove)
      el.removeEventListener('contextmenu', onContextMenu)
      window.removeEventListener('keydown', onKeyDown)
    }
  }, [activeTool, gl, camera])

  return <WallDraftPreview cursor={cursor} />
}

/** 橡皮筋：从最后一个已确定顶点连到光标。预览墙绝不 addNode 进 store。 */
function WallDraftPreview({ cursor }: { cursor: Point2D | null }) {
  const scope = useInteractionScope((s) => s.scope)
  const pts = draftPoints(scope)
  const last = pts.length > 0 ? pts[pts.length - 1]! : null
  if (!last || !cursor) return null

  return (
    <Line
      points={[
        [last.x, 0.01, last.y],
        [cursor.x, 0.01, cursor.y],
      ]}
      color="#0b6e5f"
      lineWidth={2}
      dashed
      dashScale={20}
    />
  )
}

import { describe, expect, it } from 'vitest'
import { useInteractionScope } from '../../store/use-interaction-scope'
import {
  draftPoints, IDLE_SCOPE, isActive, isIdle, lastDraftPoint, selectionEnabled,
} from './scope'

const drafting = (points: { x: number; y: number }[] = []) =>
  ({ kind: 'drafting', tool: 'wall', points }) as const

const reset = () => useInteractionScope.setState({ scope: IDLE_SCOPE })

describe('scope 纯函数', () => {
  it('idle 允许选择', () => {
    expect(selectionEnabled(IDLE_SCOPE)).toBe(true)
    expect(isIdle(IDLE_SCOPE)).toBe(true)
    expect(isActive(IDLE_SCOPE)).toBe(false)
  })

  it('任何活跃交互都掐断选择', () => {
    expect(selectionEnabled(drafting())).toBe(false)
    expect(isActive(drafting())).toBe(true)
  })

  it('draftPoints 在非 drafting 上返回稳定的空数组', () => {
    // 不能每次返回新数组，否则下游 memo 永远失效
    expect(draftPoints(IDLE_SCOPE)).toBe(draftPoints(IDLE_SCOPE))
    expect(draftPoints(IDLE_SCOPE)).toHaveLength(0)
  })

  it('lastDraftPoint 取最后一个已确定顶点', () => {
    expect(lastDraftPoint(IDLE_SCOPE)).toBeNull()
    expect(lastDraftPoint(drafting([{ x: 1, y: 2 }, { x: 3, y: 4 }]))).toEqual({ x: 3, y: 4 })
  })
})
