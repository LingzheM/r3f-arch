参数：层名 `core` / `viewer` / `app`。放出 `docs/m<N>-code.md` 中该层代码之前必须走完。这是把「照敲」变回「作者」的地方，不走完不放码。

## 1. 讲回来（用户不看文档）

从设计文档 §02 和 §04 里挑该层的 3 个问题问用户。要求用自己的话回答，且能在代码里指出来：

- 这一层解决什么问题，为什么在这个 M 做
- 一个不变量是什么，破坏它会看到什么现象
- 一次用户操作（点击、拖动、存档）经过这一层的哪些函数，哪一步写 store，哪一步只读

每个回答只判「对 / 不完整 / 错」，附一句纠正。错的地方就是规格书没吃透的地方：展开讲那一段，再问一次，直到答对。

## 2. 先写红测试

从 §04 该层的步骤里列出要测的不变量（纯函数、store、几何）。用户自己写测试文件，跑 `pnpm test`，粘贴结果。

- review 测试：断言是否真的能因为那个 bug 变红；有没有只测「跑不崩」的假测试。
- 测试文件的路径和名字由用户定，记进偏差表，后续文档跟用户的命名。
- 该层没有纯函数（只有渲染接线）时跳过，明写「本层无自动护栏，验收靠肉眼」。

## 3. 放码

两步都过，才把该层的 §07 追加进 `docs/m<N>-code.md`，开头一行写验证范围（D16）。提醒用户：敲完跑 verify，再 `/review`。

[模式] 型 M 只走第 1 步，问 1 个问题即可。
